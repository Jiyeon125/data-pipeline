# 대시보드 기능 회귀 감사

## 감사 결론

프로그램-연도 화면으로 전환하면서 세부사업 산출물은 입력 검증에만 남고 활성 상세 화면에는 전달되지 않았습니다. 회귀 원인은 데이터 부재가 아니라 화면 연결 단절입니다.

- `full_population_project_review_queue.csv` 3,286행은 로드·검증됐지만 `main()`에서 꺼내지 않았습니다.
- 활성 상세 함수 `_render_program_year_detail()`은 `raw_candidate_ids`를 회계유형 감사행 연결에만 사용했습니다.
- `_project_table_view()`와 회계후보 단위 `_render_candidate_detail()`은 남아 있었지만 후자는 호출되지 않았고 현재 프로그램-연도 화면 및 내부 PDF 화면 상태와 호환되지 않았습니다.
- `stable_top5_project_drilldown.csv`는 74행의 일부 안정 후보용 산출물이므로 전체 프로그램 상세의 원천으로 사용할 수 없습니다.

## 복구한 연결 계약

전체 프로그램 상세의 세부사업 원천은 `full_population_project_review_queue.csv`로 고정했습니다. 선택 프로그램-연도의 `raw_candidate_ids`를 JSON 목록으로 읽어 모든 candidate를 연결하며, 프로그램명 유사도나 추정 연결은 사용하지 않습니다.

한 프로그램-연도가 복수 회계유형을 가질 수 있으므로 candidate 하나만 고르지 않습니다. 현재 236개 프로그램-연도 중 122개가 복수 candidate를 포함합니다. 세부사업의 회계유형은 `full_population_review_work_queue.csv`의 candidate별 회계유형과 다시 대조합니다.

## 키·금액·비귀속 감사

- 세부사업 행: 3,286행
- 연결 candidate: 397개
- 후보키 `candidate_id × project_id` 중복: 0건
- 다른 프로그램 candidate 혼입: 0건
- candidate별 본예산·예산현액·지출액 합계 불일치: 각 0건
- 회계유형 불일치: 0건
- `project_performance_attributed=true`: 0건

프로그램-연도 수준에서는 225행이 프로그램 총액과 세부사업 합계가 일치합니다. 9행은 명시적으로 연결된 세부사업이 없고, 2행은 일부 회계 candidate가 데이터 확인 대상이라 세부사업 합계가 프로그램 총액보다 작습니다. 이 2행은 `019:1200:2022`, `075:2700:2022`이며 화면에서 미연결 회계행 수와 본예산·예산현액·지출액 차이를 표시합니다. 불일치를 임의 합산하거나 0으로 대체하지 않습니다.

## 복구된 상세 순서

1. 프로그램-연도 요약
2. 확인 이유·다음 질문·보고목표·집행·예산 근거
3. 연도별 관측 타임라인
4. 세부사업 재정 원인 보기
5. 회계유형별 감사자료
6. 성과계획서·성과보고서 원문 검수 이동
7. 내부 분석 근거

세부사업 표에는 세부사업 자체의 예산·현액·지출·집행률·잔액·이월·불용·재정신호와 프로그램 내 금액 기여만 표시합니다. 프로그램 보고목표는 개별 세부사업 성과로 귀속하지 않는다는 문구를 별도로 표시합니다.

## 원문 검수 이동

기본 탭에 존재하지 않는 과거 `원문 검수` 탭 요청은 사용하지 않습니다. 버튼은 프로그램·부처 필터와 `pending_internal_view`만 예약하고, 다음 렌더에서 내부 화면 위젯 생성 전에 `PDF 원문 검수`로 전환합니다. PDF 큐 미연결 부처는 버튼을 비활성화하고 이유를 표시합니다.
