# 분석 신뢰성 보강 확정 수정 계획

작성일: 2026-08-05  
상태: **Trial 조건부 승인 — 1차 생산 수정 착수**  
기준 분석시점: **필요 자료가 공개·구조화된 이후의 회계연도별 연례 사후검토**  
이 기준은 회계연도 말 당시의 정보집합이나 실시간 판단을 재현하지 않는다. 현재 자료에는
신뢰할 수 있는 `available_at`이 없어 실제 공개시점 절단은 적용하지 않는다.
기준 분석단위: 프로그램 진단은 `부처 × 프로그램 × 회계연도 × 회계유형`, 세부사업은 원인 확인 드릴다운

이 문서는 `docs/REVIEW_PRIORITY_TRIAGE_IMPLEMENTATION_PLAN.md`의 최신 후속 계획입니다.
기존 문서의 분류모델·PDF 사업특성·LLM 설명 범위는 폐기하지 않지만 이번 생산 수정의
완료조건에는 포함하지 않습니다.

## 1. 목적과 금지 결론

현재 점검대기열에서 시점 누수, 회고 환류 혼입, 성과달성률 과대해석, 결측 구성요소의
암묵 재가중을 제거합니다. 결과는 실패·낭비·감액·폐지·사업효과를 자동 판정하지 않고,
추가 설명과 원문 확인이 필요한 순서를 지원합니다.

다음은 금지합니다.

- 프로그램 성과를 세부사업 성과로 귀속
- 회고적 T+1·T+2 결과로 과거 시점의 현재 진단 변경
- 방향·단위·정의가 불명확한 성과지표 간 상대 성과 비교
- 결측 구성요소를 0점으로 바꾸거나 남은 변수로 자동 재가중
- 비교집단 임계값을 shadow 검증 없이 생산 기준으로 승격
- PDF·LLM 추론값을 정량 판정에 사용
- 단일 점수를 위험확률 또는 정책 결론으로 표현

## 2. Trial 최종 판정

- 판정: **조건부 진행**
- 확신도: **0.91**
- 독립성 수준: 세 서브에이전트 병렬 심사 + 격리된 로컬 소수의견, 1회 교차반대신문,
  별도 최종 판정 서브에이전트
- 한 문장 결론: P0 정확성·의미 경계는 즉시 생산 수정하고, 새 비교군 기준과 신호
  프로파일은 shadow 결과가 통과할 때만 생산으로 승격합니다.

- Target: 직전 조사에서 제안한 최소·중간·확장 개선안
- Decision question: 현재 저장소에 어떤 범위까지 즉시 생산 반영할 것인가
- 대안 A: 현상 유지와 경고문만 추가
- 대안 B: 모든 개선안을 한 번에 생산 반영

### 2.3 반대신문에서 강등된 주장

- `n=20`은 방어적 후보값이지만 최적 기준으로 확인되지 않았습니다.
- 전체행 기준 97.7% 커버리지는 지표별 유효표본과 사업 동질성을 보장하지 않습니다.
- 신호 프로파일이 실제 검토시간이나 정확도를 개선한다는 점은 아직 예측입니다.
- 12건 고정 사용자 검증은 근거 없는 수이므로 층화 사례 검증으로 바꿉니다.
- 환류정보는 삭제하지 않고 현재 진단에서만 분리해 회고 영역에 보존합니다.

## 3. 범위 결정

### 3.1 지금 생산 반영

1. 반복 신호를 사업×회계연도 as-of 누적으로 계산
2. T+1·T+2 환류를 현재 레인·독립신호 수·강한 단일·우선단계·정렬에서 제거
3. 환류 원값과 회고적 맥락은 별도 필드·화면·다운로드에 보존
4. 공식 달성률을 `보고된 목표 달성 상태`로 한정
5. 방향·단위·지표 연속성이 불명확하면 성과 추세·교차사업 상대비교 보류
6. 부분 구성요소 `signal_score`의 암묵 재가중 차단
7. 프로그램 성과 비귀속과 프로그램/회계/세부사업 grain 표시
8. 보고서·다운로드·화면의 현재 진단/회고 환류 구분

### 3.2 shadow 검증 후 생산 승격

1. 지표별 고유 분석단위 기준 `valid_peer_n`
2. n=10·20·30 민감도
3. 동점 보정 경험 백분위
4. 비교집단 최소표본에 따른 `HOLD_COMPARISON_GROUP`
5. 비교군 계층 fallback
6. 신호 프로파일과 진단유형을 기본 UI로 전환
7. `legacy_review_sort_score` 탐색 정렬로 역할 축소

### 3.3 이번 구현에서 제외

- PDF 사업유형·성과발현시차·집행집중·외부의존요인 신규 추출
- LLM 설명·후속질문 자동 생성
- LLM confidence 기반 자동승격
- 기대성과 회귀·강건회귀·비선형 모델·ML 잔차
- Isolation Forest·군집·DEA·시계열 예측
- React·DB 대시보드 전환

## 5. P0-1 반복 신호 as-of 수정

### 5.1 현재 원인

- `src/analytics/m3_financial_signals.py::build_repeated_signals`
  - `classification_project_id` 전체기간 집계
- `attach_signal_types`
  - `classification_project_id`만으로 many-to-one 결합

### 5.2 수정 계약

- 전체기간 설명 통계 `project_signal_recurrence`는 유지
- 운영 신호는 별도 as-of 테이블에서 계산
- as-of 기본키: `classification_project_id × fiscal_year`
- 각 연도 행은 `fiscal_year <= 기준연도` 자료만 사용
- 반복횟수·유효연도·반복률·연속2년을 모두 기준연도별 계산
- `attach_signal_types`는 사업 ID와 연도를 함께 결합
- 미래 행을 추가해도 과거 행 신호는 변하지 않음

### 5.3 정보 가용시점 한계

as-of는 실시간 연중 판단이나 회계연도 말 당시 정보집합이 아니라, 필요한 자료가
공개·구조화된 뒤 수행하는 연례 사후검토의 회계연도 축 누적입니다. 성과보고서가
다음 연도에 발행될 수 있으므로 `fiscal_year`는 대상연도이며 실제 공개일시가 아닙니다.
실제 당시 시점 재현에는 향후 신뢰 가능한 `available_at`이 필요합니다.

## 7. 성과달성률 의미 경계

### 7.1 즉시 적용

- 기존 원본·분석 공식률 컬럼은 호환을 위해 보존
- 화면·보고서 명칭은 `보고된 목표 달성 상태`
- 공식률은 목표 미달/달성/혼합 상태와 원문 확인에만 사용
- 사업효과, 상대 성과, 효율성, 인과효과로 표현하지 않음
- `comparable_rate_count < indicator_count`이면 `REVIEWABLE_WITH_LIMITS`
- 공식률 또는 방향·단위 확인이 없으면 성과 추세·교차사업 비교는 null/보류

### 7.2 다년도 성과 조건

- 동일 프로그램·정규화 지표명·단위·방향
- 연속 회계연도
- 목표변경·정의변경·복수후보 없음
- 조건을 충족한 경우에만 반복 미달·초과달성 계산
- 현재 193개 인접연도 동일명 쌍과 단위 동일 187쌍은 후보 상한이며 확정 시계열이 아님

## 8. 부분 점수와 기존 가중치

- 3개 구성요소가 모두 있을 때만 `signal_score`를 계산
- 하나라도 없으면 null과 `INCOMPLETE_COMPONENTS`
- 남은 구성요소로 분모를 줄이지 않음
- 기본 UI에서 `signal_score`를 제거하거나 `legacy_review_sort_score`로 명칭 변경
- 기존 4개 가중 시나리오는 고급 민감도 QA에만 보존
- 가중치가 현재 레인·진단유형·정책 결론을 바꾸지 못함

## 9. shadow 비교군 검증

### 9.1 지표별 분석단위

| 지표 | 유효 n 기준 |
|---|---|
| 집행률 | `source_project_year_id` 중 집행분모·집행률 유효 고유행 |
| 월별 패턴 | 월별 패턴 적격 `source_project_year_id` |
| 예산변화 | 연속성·금액유형·증감률 적격 `classification_project_id × fiscal_year` |
| 프로그램 성과 | 회계행이 아닌 고유 성과 프로그램-연도 |

### 9.2 후보 비교군

1. 연도×회계유형×공식 단일 지원형태×사업분류×분야/부문×규모구간
2. 분야/부문 제거
3. 규모구간 제거
4. 연도×회계유형×공식 단일 지원형태
5. 그래도 부족하거나 지원형태 미확정이면 상대비교 보류

fallback은 shadow에서만 계산하고 `peer_definition`, `valid_peer_n`, `fallback_level`,
`peer_distinct_value_n`을 저장합니다. 전체 분포는 참고선일 뿐 생산 신호 fallback으로
사용하지 않습니다.

### 9.3 임계값 선택

- n=10·20·30 각각 계산
- 부처·회계·사업규모별 보류 행·사업 수와 예산 비중
- 레인 이동 수와 금액
- 상위 K 중복·순위 범위
- 경계 후보 leave-one-out 변화
- 표본 20 이상이어도 고유값 5개 미만이면 낮은 신뢰도
- MAD=0이면 robust z를 만들지 않고 동점 보정 백분위만 사용

통과한 하나의 기준만 생산으로 승격합니다. 최적 기준이 확인되지 않으면 현 절대신호를
유지하고 상대신호를 보류합니다.

| `target_adequacy_signal` | 반복 초과와 목표 불변/하락 | 목표변경 자료가 있는 범위만 |
| `low_execution_target_met_cooccurrence` | 저집행과 보고목표 달성 동시 관측 | 효율성 확정 표현 금지 |
| `data_quality_risk` | 분모·매칭·단위·원문 위험 | 기존 품질 플래그 재사용 |
| `reviewability_status` | 현재 판단 가능 범위 | 신호별 적격성과 hold 이유 보존 |

진단유형은 `집행 지연 의심`, `저집행과 보고목표 미달 동시 관측`,
`예산 확대 후 보고목표 개선 확인 불가`, `반복 목표 미달`,
`반복 초과달성·목표 적정성 검토`, `저집행과 보고목표 달성 동시 관측`,
`현재 구조화 신호 미검출`, `판단 보류`, `데이터 품질 검토 필요`로 제한합니다.
`비효율`, `실패`, `정상`, `구조조정 대상`은 사용하지 않습니다.

## 11. PDF·LLM 단계

이번 생산 수정에는 포함하지 않습니다. 후속 중간안은 기존 `dataclass + strict JSON
Schema + 원문 인용 검증` 패턴을 재사용합니다.

- 프로그램 특성 키: `ministry_code × fiscal_year × source_program_code`
- 성과지표 특성 키: `source_indicator_id`
- 프로그램 특성을 세부사업 전체에 복제하지 않음
- `NO_RELEVANT_CONTENT`는 value null, UI에서 문서 근거 없음으로 렌더링
- 직접 근거와 사람 확인만 분석 사용
- 간접추론은 표시 후보로만 유지
- 사람값이 자동값보다 우선하며 재실행 시 보존
- 원본·페이지 hash, model, prompt/schema version, request hash 저장
- 상위후보·사용자선택·신호충돌 사례만 2차 처리
- 외부 호출은 명시 비용상한 없이는 실행하지 않음
- LLM은 숫자 계산·등급·순위 변경을 하지 않음

## 12. UI·보고서·다운로드

### 12.1 즉시 수정

- 프로그램-연도-회계행 grain 표시
- `성과 미달`을 `보고된 목표 미달 지표`로 변경
- 현재 진단과 회고 환류 카드·문구·필터 분리
- 부분 점수는 정렬값으로 사용하지 않음
- 다운로드에 `analysis_version`, `generated_at`, grain, 현재/회고 구분 포함
- 보고서 수치를 `analysis_summary.json`과 대조

### 12.2 shadow 통과 후

- 단일 순위 대신 진단유형별 대기열
- 대기열에는 주 진단 1개·다음 행동만 표시
- 상세카드에 전체 신호 프로파일, 원시값, 비교군, n, 중앙값, IQR, 백분위, hold 표시
- 자동 추출·사람 검토·원문 근거를 구분
- 가중치는 판정이 아닌 사용자 관심사 기반 정렬임을 표시

### 12.3 사용자 행동 공개 관문

부처·회계·레인·보류상태를 층화한 소규모 사례로 다음을 확인합니다.

- 무엇을 먼저 확인할지 식별 가능
- 원문·세부사업 근거 위치를 찾을 수 있음
- 보류 이유를 인지함
- 프로그램 성과를 세부사업 성과로 오인하지 않음
- 다음 확인 질문을 작성할 수 있음

고정 표본 수보다 층화 범위와 실패 사례를 우선합니다.
