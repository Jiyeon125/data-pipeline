# 멘토링 지침 반영 추적 감사

## 기술 요약

현재 저장소는 원본 보존, 분석 단위 분리, 구조적 결측, 사업계보, 분석 제외,
집행 신호 분해, T+1·T+2 재정 코호트에서는 멘토링 원칙을 상당 부분
반영했습니다. 그러나 지금 상태를 성과·재정 통합 분석의 기준선으로 그대로
사용하면 안 됩니다.

가장 큰 차단 사유는 다음 다섯 가지입니다.

1. 기금 2,264개 사업-연도는 모두
   `UNCONFIRMED_FUND_PLAN_DENOMINATOR`로 제한했습니다. 월별 원천의
   `ANEXP_BDG_CAMT`가 기금의 지출계획현액이라는 공식 필드 계약은 여전히
   확인되지 않았으므로 기금 집행률·집행 신호·순위는 산출하지 않습니다.
2. 프로그램-연도 558행 중 193행(34.6%)이 복수 회계유형입니다. 중기부
   성과·재정 공동분석 21행 중에는 17행(81.0%)이 복수 회계유형인데 기존
   파일럿은 회계유형별 집행률을 분리하지 않았습니다.
3. 금액 이벤트 264,988행의 `amount_type`은 의미 표준값이 아니라 API 원본
   필드명이며, `confirmed_flag`와 `unit_confirmed`가 모두 거짓입니다.
4. 재정수단 순위 적격 3,066행은 사람 확정값이 없습니다. 3,053행은
   `RULE_CANDIDATE`, 13행은 `MANUAL_REVIEW`인데 현재 적격 플래그는
   `UNKNOWN` 여부만 확인합니다.
5. 보고서와 트래커 일부 수치가 최신 재실행 결과와 다릅니다. 현재 ranking v2는
   6,130행인데 트래커에는 6,290행이 남아 있고, 월별 적격은 3,252행인데 일부
   보고서 문장에는 3,328행이 남아 있습니다.

따라서 현재 종합 판정은 **Needs revision**입니다. 재정 원자료와 개별 품질
산출물은 계속 사용할 수 있지만, 기존 중기부 통합 집행률·커버리지 보고서와
재정수단 비교 신호는 아래 P0 조치 전에는 분석 결론으로 사용하지 않습니다.

- 기준일: 2026-07-27

상태 정의:

- `완료`: 실제 코드와 실데이터 산출물로 검증됨
- `부분`: 일부 범위·필드·부처만 구현됐거나 검증이 덜 됨

- `대기`: 선행 원자료, PDF 별첨, LLM 허용 또는 사람 검수가 필요함

## P0: 성과자료를 더 붙이기 전에 바로잡을 계약

### 1. 기금 분모를 확인 전 `APPLIED`로 두지 않기

현재 월별 원천의 `ANEXP_BDG_CAMT`는 `current_budget_amount`로 정규화되어
있지만 데이터사전에는 “세출예산현액 잠정 매핑”이라고 기록되어 있습니다.
열린재정의 공식 월별 지출운용상황 화면은 이 자료를 “월별 세출 예산/기금 운용
집행실적”이라고 설명하고 예산은 이월·추경 등을 포함한 현행예산이라고
설명합니다. 다만 API 필드 `ANEXP_BDG_CAMT`가 기금의 지출계획현액이라는
필드 수준 정의는 제공하지 않습니다.

2026-07-28 적용 결과:

- 기금 2,264행 전체를 `UNCONFIRMED_FUND_PLAN_DENOMINATOR`로 변경했습니다.
- 확정 분모와 집행률은 null이며, 원천 `current_budget_amount`는 변경하지
  않았습니다.
- core 기금 1,509행은 예산·재정구조 분석과 전체 점검 모집단에는 유지하지만
  집행 신호와 집행 순위 적격은 0행입니다.
- 중기부 2024년 `중소기업수출촉진지원 × 기금`의 종전 87.7894%는 철회하고,
  분모 확인 전까지 `DATA_REVIEW`로만 표시합니다.
- 공식 근거:
  [열린재정 월별 지출운용상황](https://opms.openfiscaldata.go.kr/op/ko/sd/UOPKOSDA01),
  [열린재정 Open API](https://opms.openfiscaldata.go.kr/op/ko/ds/UOPKODSA01)

### 2. 프로그램 재정을 프로그램×회계유형×연도로 먼저 집계하기

현재 프로그램-연도 집계는 회계별로 계산된 사업 분자·분모를 모두 합쳐 하나의
집행률을 만듭니다. 이는 금액 보존에는 유효하지만, 멘토링의 회계유형별 분리
해석과 맞지 않습니다.

권장안:

- `program_account_year_financial`을
  `부처 × 프로그램 × 회계유형 × 회계연도`로 생성합니다.
- `program_year_financial`의 총예산·총지출은 구조 설명용으로 유지할 수 있지만,
  혼합 회계 프로그램의 총집행률은 점검 신호·표준화·순위에 사용하지 않습니다.
- 프로그램 성과는 여전히 프로그램 전체 성과입니다. 이를 특정 회계 또는
  세부사업 성과로 배분하지 않고, 같은 프로그램 아래 회계유형별 재정 프로필을
  병렬로 보여줍니다.
- 기존 `mss_same_year_budget_check`는 이 재산출이 끝날 때까지 롤백 상태를
  유지합니다.

### 3. 금액 이벤트의 의미와 단위를 확정하기

`budget_amount_events.parquet` 264,988행의 `amount_type`은
`Y_YY_MEDI_KCUR_AMT` 같은 원천 필드명이고, 확정된 의미 표준값이 아닙니다.

권장안:

- 원천 필드와 의미 필드를 분리합니다:
  `source_field`, `amount_type_candidate`, `amount_type_confirmed`,
  `amount_type_status`.
- 최소한 `national_assembly_final_budget`, `supplementary_budget`,
  `current_budget`, `current_expenditure_plan`, `expenditure`,
  `settlement`, `carryover`, `unused_amount`를 공식 정의가 확인된 자료에서만
  확정합니다.
- `KCUR`, `FRC`의 의미와 환산 단위를 공식 명세로 확인하기 전에는 서로
  합산하지 않습니다.

### 4. 재정수단 후보값을 확정값처럼 비교집단에 넣지 않기

현재 `fiscal_instrument_ranking_eligible`은 재정수단이 `UNKNOWN`이 아니면
참입니다. 이 때문에 사람 검수 전 `RULE_CANDIDATE`도 재정수단 비교집단에
들어갑니다.

권장안:

- 확정 비교에는 `classification_status == VERIFIED`를 요구합니다.
- `RULE_CANDIDATE` 비교는 별도 민감도 시나리오로만 유지하고 화면에
  “규칙 후보 기반”이라고 표시합니다.
- 현재 준비된 UNKNOWN 18개 우선검수는 예산 커버리지 개선용이며, 완료 전에는
  재정수단별 순위와 상대 신호를 확정하지 않습니다.

### 5. 산출물 수치와 트래커를 현재 입력으로 재동기화하기

완료 상태와 과거 검증 메모는 당시 실행의 증거이지 현재 산출물의 증거가
아닙니다. 현재 파일 해시와 요약 JSON을 기준으로 보고서·트래커의 수치를
동기화하고, 파생 보고서 안에서도 같은 수치가 반복되는 곳을 검사해야 합니다.

## 우선순위별 적용 순서

### P0 — 지금 바로, 성과 PDF 결합 전

1. 기금 지출계획현액의 공식 필드와 단위를 확인합니다.
2. `program_account_year_financial`을 만들고 혼합 회계 총집행률을 신호에서
   제외합니다.
3. 중기부 파일럿을 회계유형별 재정 프로필로 재산출합니다.
4. 금액 이벤트 의미유형·단위를 후보/확정으로 분리합니다.
5. 재정수단 `RULE_CANDIDATE`와 `VERIFIED`의 분석 적격성을 분리합니다.
6. 현재 JSON 기준으로 보고서와 트래커의 오래된 수치를 동기화합니다.

### P1 — 사용자가 분리하는 성과 별첨으로 진행

1. 수기 스키마에 `measurement_formula`, `reported_target`, 지표유형,
   목표변경 필드, 통제된 검수상태를 추가합니다.
2. 중기부 2022년 `소상공인·전통시장지원` 별첨을 먼저 확인합니다.
3. 성과 원문 미기재, 문서 미발간, 수기 누락, 파싱 실패를 구분합니다.
4. 프로그램별 복수지표 집계를 단순 평균 없이 완성합니다.
5. 중기부 한 부처에서 동년도 괴리 유형과 사례카드가 재현되는지 확인한 뒤 다른
   부처로 확장합니다.

### P2 — 재정수단·평가·예산변화 근거

1. UNKNOWN 18개를 사람 검수하고 후보 비교집단 영향을 재산출합니다.
2. 의무지출과 재정수단별 기본 규모지표의 공식 근거를 확보합니다.
3. 평가 이벤트와 예산변화 근거 이벤트를 구축합니다.
4. T+1·T+2에 성과와 공식 예산변화 사유를 연결합니다.

### P3 — 마지막

1. 복수 가중치 시나리오와 변수 제거·순위상관·상위 K 중복을 검증합니다.
2. 검증된 결과만 대시보드와 사례카드에 반영합니다.
3. LLM은 수기 파일럿과 골드셋 계약이 안정된 뒤 문서 구조화 보조로 추가합니다.

## 현재 사용할 수 있는 것과 사용할 수 없는 것

사용 가능:

- 원본 예산·월별·결산 데이터와 원본 추적 필드
- broad/core/ranking v2의 목적별 모집단 구조
- 회계유형별 재정 EDA
- 구조적 결측, 관측경계, 사업관계 후보
- 분석 제외와 금액 커버리지
- 재정 신호의 기술적 탐색과 T+1·T+2 분리 코호트
- 중기부 수기 성과지표 63행의 원본 보존 및 프로그램 매칭 상태

현재 결론에 사용 불가:

- 기금 집행률이 적정 분모로 확정됐다는 주장
- 혼합 회계 프로그램의 총집행률을 이용한 성과·집행 해석
- 기존 `mss_same_year_budget_check`의 통합 집행률·커버리지 결론
- 미검수 재정수단 후보를 확정 비교집단으로 사용한 순위
- 성과 미흡이 예산 감소를 유발했다는 해석
- 5개 부처 성과자료가 모두 분석 준비됐다는 주장
- 최종 복합점수·전체 순위·정책 판정
