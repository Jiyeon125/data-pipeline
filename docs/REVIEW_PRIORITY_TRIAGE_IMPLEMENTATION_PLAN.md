# 점검 우선순위 트리아지·분류모델 구현 계획

작성일: 2026-08-01
상태: **구현 대기** — PDF→데이터셋 LLM 파이프라인이 안정화된 뒤 착수합니다.

## 1. 한 문장 목표

재정·성과관리 실무자가 긴 원문을 먼저 읽지 않고도 **어떤 세부사업의 어떤 근거부터
확인해야 하는지** 알 수 있는 점검 업무대기열을 만듭니다.

이 시스템은 실패·낭비·감액·폐지를 자동 판정하지 않습니다.

## 2. 최종 흐름

```text
PDF 파싱
→ 성과·재정 마스터 결합
→ 파생변수 생성
→ 비교 가능한 사업끼리 상대비교
→ 네 가지 독립 점검신호 생성
→ 반복·복수 신호 중심의 업무단계 분류
→ 전체·부처별 점검순서 산출
→ 공식 평가결과 분류모델을 보조열로 연결
→ LLM이 이유·반대근거·확인사항 설명
→ 전문가 최종 판단
```

## 3. PDF 파싱 파이프라인과의 경계

### 파싱 파이프라인의 역할

문서에 존재하는 사실과 근거만 반환합니다.

- 부처, 연도, 프로그램명·코드
- 성과지표명, 단위, 방향
- 계획목표, 보고목표, 실적, 공식 달성률
- 목표변경 전·후 값과 변경 사유
- 성과지표 유형 후보
- 기대 성과시차 후보
- 사업 전달방식·재정수단 후보
- 출처 파일, 원문 페이지, 근거문장
- 추출·대조·사람검수 상태

### 우선순위 엔진의 역할

- 파싱값과 예산·집행·결산을 연결합니다.
- 산식과 동료집단을 적용합니다.
- 독립 신호와 업무순서를 만듭니다.
- 데이터가 없거나 불확실한 값을 0점으로 만들지 않습니다.

### LLM이 하지 않는 일

- 최종 순위 직접 결정
- 사업 필요성·감액 필요성 임의 판정
- 누락된 수치 추정
- 분류모델 결과 변경
- 프로그램 성과를 세부사업 성과로 귀속

## 4. 분석 단위

### 신호 생성 단위

```text
부처 × 프로그램 × 회계연도 × 회계유형
```

성과지표는 프로그램 단위이므로 이 수준에서 성과 맥락을 만듭니다.

### 최종 점검행

```text
부처 × 프로그램 × 세부사업 × 회계연도 × 회계유형
```

세부사업에는 자기 예산·집행·구조 신호만 붙입니다. 프로그램 성과는
`상위 프로그램 성과 맥락` 열로만 표시합니다.

### 월별 집행 단위

```text
부처 × 회계연도 × 집행연월 × 회계 × 프로그램 × 단위사업 × 세부사업
```

## 5. 네 가지 독립 점검신호

네 신호는 0~100의 `동료집단 점검강도 백분위`로 표현할 수 있지만 기본 화면에서
합산하지 않습니다.

| 신호 | 실무 질문 | 핵심 파생변수 | 기본 해석 |
|---|---|---|---|
| 성과 | 목표달성이 일부·전반·반복 중 무엇인가 | 미달비율, 중앙부족, 최악부족, 반복 미달 | 성과 설명 또는 지표 재설계 검토 |
| 집행 | 같은 성격 사업보다 집행이 취약한가 | 집행률, 동료집단 하위꼬리, 반복 저집행, 연말집중 | 집행사유 확인 |
| 성과–예산 불일치 | 성과와 후속예산 방향이 어긋나는가 | 성과미달×실질증액, T+1·T+2 방향 | 예산환류 설명 필요 |
| 예산구조 | 프로그램 내부 배분이 크게 달라졌는가 | top1·top3, 정규화 HHI, HHI 변화, 재배분 거리 | 구조변경·집중 원인 확인 |

### 5.1 성과 신호

지표 `j`의 공식 달성률을 `r_j`라고 합니다.

```text
indicator_coverage = 유효 달성률 지표 수 / 전체 지표 수
under_target_share = count(r_j < 100) / count(valid r_j)
median_shortfall = median(max(0, 1 - r_j / 100))
worst_shortfall = max(max(0, 1 - r_j / 100))
repeated_under_rate = 미달 관측연도 수 / 유효 관측연도 수
```

평균 달성률 하나는 사용하지 않습니다. 과도달성이 미달을 상쇄할 수 있기 때문입니다.

### 5.2 집행 신호

분모가 확인된 집행률만 사용합니다.

```text
execution_gap = max(0, 1 - execution_rate)
peer_execution_tail = 1 - ECDF_peer(execution_rate)
repeated_low_rate = 저집행 연도 수 / 유효 집행연도 수
q4_share = (12월 누계 - 9월 누계) / 12월 누계
december_share = (12월 누계 - 11월 누계) / 12월 누계
```

80%·90% 같은 절대기준과 동료집단 하위 10%·20%를 함께 보여줍니다. 집행률 100%
초과는 위험점수가 아니라 분모·조인·회계조정 검증으로 보냅니다.

### 5.3 성과–예산 불일치 신호

동일 금액유형을 GDP 디플레이터로 실질화합니다.

```text
real_budget_t = nominal_budget_t / deflator_t
real_growth_h = real_budget_(t+h) / real_budget_t - 1
underperformance_increase_h = performance_shortfall × max(real_growth_h, 0)
```

T+1과 T+2를 합치지 않습니다. 성과 양호+예산 감소는 대칭적인 문제점수가 아니라
구조변경 맥락으로 따로 표시합니다.

### 5.4 예산구조 신호

세부사업 예산비중을 `s_k`라고 합니다.

```text
HHI = sum(s_k²)
normalized_HHI = (HHI - 1/n) / (1 - 1/n), n >= 2
reallocation_distance = 0.5 × sum(|s_(k,t+1) - s_(k,t)|)
```

세부사업이 하나인 프로그램은 `단일 구성`이지 자동 고위험이 아닙니다. 코드변경·통합·
분할 후보는 연결을 확인한 뒤 변화량을 계산합니다.

## 6. 동료집단

기본 동료집단은 다음과 같습니다.

```text
회계연도 × 회계유형 × 검증된 재정수단 × 기대 성과시차
```

필요하면 전달방식을 추가합니다.

- 즉시 서비스
- 연간 보조·출연
- 하위기관 집행
- 다년 R&D
- 다년 시설
- 융자·보증 등 금융지원
- 미분류

표본이 작으면 부처를 먼저 제거해 비교집단을 넓힙니다. 그래도 작으면 상대백분위를
만들지 않고 절대기준과 `소표본` 경고만 표시합니다. 최소 표본 수는 실제 분포와
민감도 검증 후 확정합니다.

## 7. 두 개의 업무대기열

### 7.1 데이터 검증 대기열

정책 우선순위와 분리합니다.

- 금액 단위·금액유형 미확정
- 집행률 분모 미확정
- 프로그램 PARTIAL·UNMATCHED
- 성과 원문·산식 차단 오류
- 키 충돌·중복·관측연결 문제

표시값은 `DATA_FIRST`입니다. 정책적으로 나쁘다는 뜻이 아닙니다.

### 7.2 정책 점검 대기열

```text
REPEATED_OR_MULTIPLE  반복 신호 또는 독립 신호가 여러 개
STRONG_SINGLE         매우 강한 단일 신호
SINGLE_REVIEW         보통 단일 신호
CONTEXT_REVIEW        구조변경·성과양호+감액 등 맥락 확인
MONITOR               현재 관측에서 우선 신호 없음
```

`MONITOR`를 `안전`으로 표현하지 않습니다.

## 8. 전체·부처별 점검순서

가중합 대신 다음 사전식 정렬키를 사용합니다.

```text
1. 업무대기열 단계
2. 반복 신호 유형 수 내림차순
3. 독립 신호 유형 수 내림차순
4. 가장 강한 유형의 동료집단 백분위 내림차순
5. 근거 신뢰도
6. 실질 예산 영향규모 내림차순
7. 안정적인 후보 ID
```

예산규모는 위험이 아니라 같은 수준 후보의 검토 파급효과입니다.

- 전체 순서: 비교 가능한 전체 동료집단에서 계산
- 부처별 순서: 같은 규칙을 적용하되 부처 내부 영향규모·업무순서 계산

## 10. 사용자에게 보여줄 설명 형식

### 예측 이유

> 같은 유형 사업 중 집행률이 하위 12%이고 저집행이 2년 반복됐습니다. 상위
> 프로그램은 성과지표 3개 중 2개가 목표에 미달했지만 다음 연도 실질예산은 14%
> 증가했습니다. 독립 신호 3개가 함께 나타나 우선 검토 단계로 분류했습니다.

### 반대 근거

> 다년 R&D 사업으로 성과가 늦게 나타날 가능성이 있으므로 사업일정과 기대
> 성과시차를 확인해야 합니다.

### 다음 행동

> 저집행 사유, 목표변경 근거, 다음 연도 증액 사유를 원문에서 확인합니다.

설명은 다음 네 질문에 답해야 합니다.

1. 왜 지금 봐야 하는가
2. 무엇과 비교했는가
3. 어떤 반대해석이 가능한가
4. 실무자가 다음에 무엇을 확인해야 하는가

## 11. 공식 평가결과 Classification 모델

기본 업무대기열을 먼저 완성한 뒤 보조 신호로 추가합니다.

### 첫 파일럿 타깃

```text
y_cut = 1  if official_result == "감액"
y_cut = 0  if official_result in {"정상추진", "사업개선"}
```

현재 확인된 2026년 4개 부처 공개결과는 524행이고, 2024 세부사업과
`부처×사업명×회계`로 정확히 연결된 400행 중 감액 이진 파일럿 적격은 397행입니다.

```text
감액 171 : 비감액 226
```

5분류는 정상추진·통합·폐지 표본이 너무 적어 현재 사용하지 않습니다. 사업 필요성
상·중·하는 최종 감액결과와 다른 타깃이므로 문항별 전문가 라벨이 확보된 뒤 별도
모델로 만듭니다.

### 첫 모형

- 표준화 수치변수 + 원-핫 범주변수 로지스틱 회귀
- 부처코드·사업명·고유 ID는 기본 입력에서 제외
- 평가시점 이후 예산과 공식 결과를 암시하는 문구 제외
- 프로그램 성과는 세부사업의 상위 맥락 변수로만 사용

현재 환경에는 `scikit-learn`이 없습니다. 모델 구현 착수 시 명시적 의존성으로 추가하고
자체 최적화 코드는 만들지 않습니다.

### 검증

- leave-one-ministry-out
- 프로그램 그룹 분할
- 향후 과거연도 학습→미래연도 검증
- balanced accuracy, macro F1, 감액 PR-AUC
- Brier score와 확률 보정
- precision@K·recall@K
- 부처·회계·규모별 성능

전체 정확도 하나만으로 채택하지 않습니다.

### 상·중·하 표시

분류모델은 먼저 보정된 확률을 냅니다.

```text
P(공식 감액결과 | 평가 이전 파생변수)
```

상·중·하 경계는 0.5 같은 임의값이 아니라 전문가 검토 가능 건수와 감액 누락비용을
기준으로 precision-recall 곡선에서 정합니다. 이 값의 이름은 `사업 필요성`이 아니라
`공식 감액결과 예측 가능성`입니다.

## 12. LLM 설명 계약

LLM은 모델 출력과 근거만 받아 자연어로 설명합니다.

```json
{
  "predicted_class": "CUT_REVIEW_HIGH",
  "calibrated_probability": 0.73,
  "positive_contributors": [],
  "negative_contributors": [],
  "raw_feature_values": {},
  "peer_percentiles": {},
  "source_evidence": [],
  "model_version": "...",
  "feature_cutoff_date": "..."
}
```

허용 출력:

- 예측 이유
- 예측을 낮추는 반대 근거
- 추가 확인사항
- 근거 부족 여부

금지 출력:

- 모델 등급 변경
- 제공되지 않은 숫자·사실 생성
- 감액·폐지 확정 표현
- 근거 없는 인과관계

가능하면 먼저 규칙형 문장 템플릿으로 설명을 만들고, LLM은 문장 다듬기와 원문 근거
요약에만 사용합니다.

## 13. 구현 순서

### 단계 0. 착수 조건

- PDF 파싱 출력 스키마가 동결됐습니다.
- 4개 부처 입력에서 필수 필드 누락·근거상태가 집계됩니다.
- 파싱 재실행 시 행과 키가 안정적으로 재현됩니다.

### 단계 1. 성과 파생변수

- 지표 사용가능률
- 미달비율
- 중앙·최악 달성부족
- 반복 미달
- 목표변경·산식검토 가드레일

### 단계 2. 집행·동료집단

- 올바른 회계별 분모
- 절대 기준과 ECDF
- 반복 저집행
- 4분기·12월 집중

### 단계 3. 환류·구조

- T+1·T+2 실질 예산증감
- 비대칭 불일치
- 정규화 HHI·변화
- 재배분 거리

### 단계 4. 독립 신호 마스터·대기열

- 데이터 검증·정책 점검 분리
- 전체·부처별 순서
- 유형별 큐
- 설명에 필요한 원값·백분위·근거 연결

### 단계 5. 사례 검증·대시보드

- 상위 후보와 반례 원문 확인
- 업무대기열·사업상세·동료비교·원문 이동
- `안전` 대신 `현재 관측에서 우선 신호 없음` 사용

- 공식 결과·특징 시점 정렬
- 로지스틱 회귀 기준선
- 부처 단위 외부검증
- 보정확률과 설명 기여도 생성

### 단계 7. LLM 설명 연결

- 모델·규칙 결과를 잠금 입력으로 전달

## 14. 완료 기준

- 전체 후보가 데이터·정책·모니터 중 하나의 상태를 갖습니다.
- 결측을 0점으로 대체하지 않습니다.
- 회계유형과 T+1·T+2를 섞지 않습니다.
- 프로그램 전체금액과 분석부분합계를 분리합니다.
- 프로그램 성과의 세부사업 귀속은 0건입니다.
- 전체·부처별 업무순서가 동일한 규칙으로 재현됩니다.
- 각 후보에서 원값·동료집단·근거·다음 행동을 확인할 수 있습니다.
- 상위 후보와 반례의 원문 검토 결과가 기록됩니다.
- 분류모델은 무작위 정확도가 아니라 부처 외부검증과 보정도를 통과합니다.
- LLM 설명의 숫자·근거가 입력과 모두 일치합니다.
- 산출물·테스트·의사결정 근거가 `docs/WORK_LOG.md`에 기록됩니다.

## 15. 채택하지 않는 방식

- 성과·집행·환류·구조를 임의 가중합한 단일 위험점수

- 공식 감액결과를 사업 필요성의 정답으로 사용
- 분류모델 검증 전 기본 업무순서에 확률 합산

## 19. 신호별 수학 보강

### 19.1 성과: 미달비율의 소표본 보정

현재 원 미달비율은 다음과 같습니다.

```text
raw_under_rate = 미달 지표 수 k / 유효 지표 수 n
```

원 비율과 `n`은 그대로 보여주고, 정렬 보조값에는 Jeffreys 형태의 완만한 보정을
후보로 사용합니다.

```text
smoothed_under_rate = (k + 0.5) / (n + 1)
```

예를 들어 `1개 중 1개 미달`은 0.75, `2개 중 2개 미달`은 약 0.833이 되어 둘 다
강한 신호이면서 근거량 차이도 반영됩니다. 이 값은 미달의 진짜 확률이 아니라
소표본 동률을 완화하는 정렬 보조값입니다. 원 비율을 대체하거나 정책 기준으로
사용하지 않습니다.

미달 여부와 부족 크기는 분리합니다.

```text
gap_ij = max(0, 1 - attainment_rate_ij / 100)
median_gap_i = median(gap_ij)
worst_gap_i = max(gap_ij)
```

성과 화면에는 다음 벡터를 함께 둡니다.

```text
raw_under_rate
smoothed_under_rate
median_gap
worst_gap
valid_indicator_count
formula_review_share
```

반복 미달도 `미달 연도 수 / 유효 연도 수`와 유효 연도 수를 함께 표시합니다.
현재 관측창이 짧으므로 `2개 이상 연도에서 반복`을 우선 설명하고, 베이지안 사후확률
또는 구간은 가정과 의존성을 검증한 뒤 보조열로만 추가합니다.

### 19.2 집행: 절대 기준·상대 기준·집행시점 분리

집행률 하나를 종합점수로 바꾸지 않고 세 질문으로 나눕니다.

```text
absolute_gap = max(0, 1 - execution_rate)
relative_tail = 1 - ECDF_g(execution_rate)
timing_delay_area = mean_m(max(0, peer_median_cumulative_share_m
                                  - project_cumulative_share_m))
```

- `absolute_gap`: 실제로 얼마나 덜 집행됐는지
- `relative_tail`: 같은 성격 사업 중 어느 정도 하위인지
- `timing_delay_area`: 연말 한 시점이 아니라 연중 집행곡선이 동료보다 얼마나 늦었는지

80%·90% 고정 기준과 동료집단 하위 10%·20%는 병렬로 유지합니다. 강한 집행 신호는
단일 기준 통과가 아니라 다음 중 하나로 정의할 후보입니다.

```text
반복 저집행
OR 절대 기준과 상대 기준 동시 충족
OR 여러 임계값 민감도에서 반복적으로 후보로 유지
```

4분기·12월 집중, 누계감소, 100% 초과는 서로 합치지 않습니다. 누계감소와 100% 초과는
우선 `회계조정·분모·조인 확인`으로 보냅니다.

### 19.3 동료집단: 촘촘한 분할보다 계층형 후퇴

이론상 권장 동료집단은 다음과 같습니다.

```text
연도 × 회계유형 × 검증된 재정수단 × 기대 성과시차 × 전달방식
```

그러나 현재 재정수단 확정값이 없고, `연도 × 회계유형`만으로도 확정 회계유형 그룹은
8~55행이며 회계유형 결측을 포함하면 1행 그룹도 생깁니다. 모든 조건을 한 번에 넣으면
소표본이 급증합니다. 따라서 아래처럼
사전에 정한 후퇴 경로를 사용합니다.

```text
1순위: 연도 × 회계유형 × 검증된 재정수단 × 기대 시차
2순위: 연도 × 회계유형 × 검증된 재정수단
3순위: 연도 × 회계유형
4순위: 상대순위 미산출, 절대값과 소표본 경고만 표시
```

최소 그룹 크기를 지금 10·20처럼 확정하지 않습니다. 후보 최소값별로 순위 뒤집힘,
상위 K 중복률, leave-one-ministry-out 변화를 비교해 가장 작은 안정 구간을 선택합니다.
상대순위에는 반드시 `peer_definition`, `peer_n`, `fallback_level`을 저장합니다.

### 19.4 성과–예산 환류: 실질·상대 증감과 비대칭 사분면

명목 증감 대신 동일 금액유형의 실질 증감을 우선합니다.

```text
real_budget_t = nominal_budget_t / deflator_t
real_growth_i,h = real_budget_i,t+h / real_budget_i,t - 1
peer_excess_growth_i,h = real_growth_i,h - median_g(real_growth_h)
```

`peer_excess_growth`는 같은 시기 공통 물가·재정기조 변화와 비교해 해당 사업이 상대적으로
더 늘었는지 보여줍니다. T+1과 T+2는 별도 코호트와 별도 열로 유지합니다.

기본 판정은 곱셈점수보다 사분면을 사용합니다.

| 성과 | 후속 실질예산 | 기본 해석 |
|---|---|---|
| 미달 | 동료보다 증가 | 환류 설명 우선 확인 |
| 미달 | 감소 | 조정이 있었는지 확인, 자동 적정 판정 금지 |
| 양호 | 감소 | 구조변경·효율화 맥락, 위험점수 아님 |
| 양호 | 증가 | 성과 확장 맥락, 효과성 확정 아님 |

`성과부족 × 증액률` 곱은 사분면 내부의 민감도 비교에만 남기고 기본 업무순서에는
사용하지 않습니다. 기대 시차가 확인되면 그 시차를 선택하고, 확인되지 않으면 T+1·T+2
방향 일치 여부를 보여줍니다.

### 19.5 예산구조: 규모 변화와 구성 변화를 분해

프로그램 전체 실질예산 증감과 세부사업 구성 변화는 다른 현상입니다.

```text
scale_change = program_total_real_growth
normalized_HHI = (HHI - 1/n) / (1 - 1/n), n >= 2
composition_distance = 0.5 * sum_k(|share_k,t+1 - share_k,t|)
```

- `scale_change`: 프로그램 전체가 커졌는지·작아졌는지
- `normalized_HHI`: 세부사업 수 차이를 보정한 집중도
- `composition_distance`: 총액과 별개로 내부 배분이 얼마나 이동했는지

세부사업 1개 프로그램은 `단일 구성`으로 표시하고 집중 위험으로 보지 않습니다.
구성거리는 코드변경·통합·분할을 연결한 뒤에만 사용합니다. 분석부분합계는 프로그램
전체 변화처럼 표시하지 않습니다.

## 20. 신호별 신뢰도 계약

현재의 후보 전체 `evidence_status` 한 열을 다음 신호별 열로 분해합니다.

```text
performance_coverage
performance_evidence_status
execution_denominator_status
execution_peer_n
execution_peer_fallback_level
feedback_complete_t1
feedback_complete_t2
feedback_sample_horizon
structure_linkage_status
source_page_coverage
```

신뢰도가 낮다고 심각도를 0으로 만들지 않습니다. 다음처럼 처리합니다.

```text
심각도 높음 + 신뢰도 높음 → 정책 점검 대기열
심각도 높음 + 신뢰도 낮음 → DATA_FIRST 또는 근거보강 대기열
신호 미검출 + 신뢰도 높음 → MONITOR
신호 미검출 + 신뢰도 낮음 → 안전 판정 금지, 데이터 상태 표시
```

## 21. 재정 도메인 라우팅

공식 성과평가가 필요성·계획/집행 적정성·성과를 종합하더라도, 현재 데이터만으로
필요성과 정책효과를 자동 판정하지 않습니다. [2026년 통합평가 결과](https://www.mpb.go.kr/web/main/bbs/b_0001/1791)와
[기획예산처 보도설명](https://www.mpb.go.kr/web/main/bbs/b_0002/2084)도 사업별 감액이
단일 성과지표가 아니라 집행 적정성과 재정지원 성과 등을 종합한 결과임을 밝힙니다.

사업 성격은 점수가 아니라 `비교집단·적용산식·다음 행동`을 바꾸는 라우팅 변수입니다.

| 사업 성격 | 공통 신호 외 추가 확인 | 자동화 경계 |
|---|---|---|
| 일반·특별회계 서비스 | 집행률, 수혜·산출, 단위원가 | 정책효과는 별도 평가 필요 |
| 기금 | 지출계획현액 기준 집행, 기금 목적·수입·잔액 | 일반회계와 직접 비교 금지 |
| 융자·이차보전 | 공급률, 회수율, 연체율, 순재정부담 | 현금흐름 자료 없으면 점수화 금지 |
| R&D·시설 | 다년도 집행곡선, 성과시차, 계속비·이월 | 단년도 저성과·연말집중 자동 벌점 금지 |
| 보조·출연·이전 | 전달기관 시차, 최종 수혜·정산 | 중앙정부 지출만으로 최종성과 판단 금지 |
| 법정·의무 | 조정가능 비중, 제도·단가·대상 구조 | 성과미달을 즉시 감액 후보로 해석 금지 |

재정수단·의무성·성과시차가 아직 근거 확정 전이면 `UNKNOWN`으로 유지하고 공통
절대신호만 제시합니다. 근거 없는 키워드 분류를 확정 동료집단에 사용하지 않습니다.

## 22. 보강된 업무순서

전체·부처별 한 줄 순서는 점수가 아니라 다음 사전식 규칙으로 생성합니다.

```text
1. DATA_FIRST 분리
2. 반복 신호 또는 복수 독립 신호
3. 강한 단일 신호
4. 신호가 임계값 민감도에서 유지되는 정도
5. 해당 신호의 강도와 소표본 보정값
6. 신호별 근거 완전성
7. 실질 예산 영향규모
8. 안정적인 candidate_id
```

`임계값 민감도 유지율`은 다음과 같이 정의합니다.

```text
threshold_stability
= 후보로 선택된 합리적 기준 조합 수 / 전체 검토 기준 조합 수
```

이는 가중합이 아니라 “기준을 조금 바꿔도 계속 먼저 보이는가”를 나타냅니다.
예산규모는 마지막 영향도·동률 정리용이며 위험도를 만들지 않습니다. Pareto 지배관계는
상위 후보가 다른 후보보다 모든 핵심 근거에서 열등하지 않은지 확인하는 검증표로만
사용하고 기본 UI의 별도 점수로 만들지 않습니다.

## 23. 기존 방식과 보강안 비교

| 항목 | 기존 방식 | 보강안 |
|---|---|---|
| 성과 | 원 미달비율과 미달 여부 | 원값 + 소표본 보정 + 중앙/최악 부족 + 유효 지표 수 |
| 반복 | 반복 플래그·횟수 | 유효 관측연도와 반복률을 함께 표시 |
| 집행 | 고정 기준과 반복 신호의 최댓값 | 절대·상대·집행시점·회계조정 신호 분리 |
| 동료집단 | 회계유형 중심 | 확정 성격부터 사용하고 소표본 시 계층형 후퇴 |
| 환류 | 명목 T+1·T+2 증감, 일부 곱셈 | 실질·동료초과 증감, 시차별 비대칭 사분면 |
| 구조 | 집중도·맥락 플래그 | 전체규모 변화와 내부 구성거리 분해 |
| 신뢰도 | 후보 전체 CONFIRMED/LIMITED/DATA_BLOCKED | 신호별 커버리지·분모·동료수·시차 완결성 |
| 전체 순서 | 레인→반복/신호수→근거→예산 | 레인→반복/복수→민감도 안정성→강도/신뢰도→영향 |
| 공식 평가 | 외부검증·분류모델 후보 | 기본 큐와 분리된 보조열, 부처외 검증 후만 사용 |

## 24. 시행착오와 보류 결정

1. **네 신호 가중합**
   가중치의 재정 근거가 없고 서로 다른 문제를 상쇄했습니다. 기본 순위에서 제거하고
   민감도 비교에만 남겼습니다.
2. **원 미달비율만 사용**
   후보당 지표가 1~2개인 경우가 많아 동률과 과대확신이 컸습니다. 원 비율을 보존하되
   소표본 보정값과 부족 크기를 병렬로 두기로 했습니다.
3. **재정수단·시차를 한 번에 촘촘히 층화**
   현재 확정 재정수단이 없고 그룹이 작아 상대순위가 불안정해집니다. 확정된 키만 쓰고
   계층형 후퇴와 소표본 경고를 적용하기로 했습니다.
4. **명목 예산증감으로 환류 해석**
   물가와 공통 재정기조를 사업 변화로 오인할 수 있습니다. 실질 증감과 동료초과 증감을
   추가하기로 했습니다.
5. **성과 양호+감액을 성과 미달+증액과 대칭 처리**
   효율화·구조개편 가능성이 있어 같은 위험축으로 합치면 해석이 틀어집니다. 전자는
   맥락열, 후자는 환류 설명 우선 신호로 분리했습니다.
6. **후보 전체 근거등급 하나로 충분하다고 판단**
   현재 360/412행이 LIMITED여서 어느 신호가 약한지 알 수 없었습니다. 신호별 신뢰도
   계약으로 바꾸기로 했습니다.
7. **베이지안 구간을 즉시 계산하려는 시도**
   현재 환경에는 `scipy`가 없어 검토용 계산이 실패했습니다. 문서 설계 때문에 새
   의존성을 추가하지 않았고, 구현 시 분류모델 의존성과 함께 도입할지 또는 단순
   보정값만 사용할지 재현성·해석성 기준으로 결정합니다.
8. **공식 감액결과를 정답 우선순위로 사용**
   공식 결과는 필요성·계획·집행·성과를 종합한 사후 결과라 현재 정량특성의 정답과
   같지 않습니다. 분류모델은 별도 보조열과 외부 타당성 검증으로 제한합니다.

## 25. 구현 착수 전 방법론 게이트

LLM 파싱이 끝나더라도 다음을 확인하기 전에는 보강 순위를 확정하지 않습니다.

- 성과지표 방향·달성률·원문 페이지·지표 연속성 스키마가 동결됨
- 성과 소표본 보정 전후 후보 변화가 표와 사례로 검증됨
- 동료집단 후퇴 단계별 표본 수·상위 K 안정성이 확인됨
- GDP 디플레이터의 기준연도와 예산 금액유형이 문서화됨
- T+1·T+2 완결 코호트의 행 수와 제외 금액비중이 확인됨
- 프로그램 전체금액과 분석부분합계가 섞이지 않음
- 재정수단·시차·의무성은 근거 확정값만 비교집단에 사용됨
- 상위 후보·경계 후보·신호 미검출 후보의 반례 검토가 기록됨
- 기본 순위와 공식 평가 분류모델의 출력이 별도 열로 유지됨
