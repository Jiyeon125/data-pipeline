# 점검 우선순위 운영정책 결정 초안

## 결론과 권장안

사용자가 원하는 최종 화면에 맞춰 **전체 우선순위와 부처별 우선순위를 모두
제공**하되, 이를 사업의 절대적 위험도나 실패 확률로 해석하지 않는 방식을
권장합니다.

한 개의 가중치 시나리오를 정답으로 고르는 대신 네 시나리오의 상대순위 중앙값을
0~100점으로 환산합니다. 이 점수는 `점검 우선순위 점수`이며, 성과평가 점수나
삭감 판단 점수가 아닙니다.

권장 운영정책은 다음과 같습니다.

1. 데이터 검증 대상은 순위에서 먼저 분리합니다.
2. 현재 고용노동부·보건복지부·과학기술정보통신부 3개 부처 MVP에서는
   네 시나리오를 모두 계산할 수 있는 193행만 후보 비교에 사용합니다.
3. 전체 비교점수와 부처 내부 비교점수를 각각 산출하고 같은 화면에서 기준을 전환합니다.
4. 선택한 기준의 점수가 80점 이상이면 `우선점검 신호`, 90점 이상이면
   `집중점검 신호`로 표시합니다.
5. 80점 이상이면서 네 시나리오 중 3개 이상에서 상위 20%이면
   `시나리오 안정` 배지를 붙입니다.
6. 80점 이상이지만 시나리오 합의가 부족하면 `가중치 민감` 배지를 붙입니다.
7. 같은 프로그램이 2개 이상 연도에서 반복되면 반복 신호 배지를 붙이고 같은 등급 안에서 먼저 봅니다.
8. 원문 근거가 약한 지표는 검수 전까지 `잠정` 표시를 유지합니다.
9. 사업규모는 문제 정도가 아니라 검토 파급효과와 동순위 검토 순서에만 사용합니다.

이 정책은 실패·낭비·삭감 대상을 정하는 정책이 아니라, 제한된 검토 시간을
어디에 먼저 쓸지 정하는 정책입니다.

> **범위 주의:** 이 문서의 193행 기반 수치와 임계값 영향은 중기부를 제외한
> 3개 부처 MVP 결과입니다. 중기부는 별도 파일럿 산출물에 남아 있으며,
> 4개 부처 통합 마스터와 전체 순위는 아직 영구 산출물로 생성되지 않았습니다.

## 전체 순위를 만들 때의 제한

현재 순위 적격 193행에서 네 시나리오의 Spearman 상관은 0.646~0.917이지만,
모든 시나리오의 공통 Top 5와 Top 10은 모두 0행입니다. 후보별 전체 순위범위
중앙값은 45위, 최댓값은 124위입니다.

큰 흐름은 유사하지만 상위권은 가중치에 따라 바뀝니다. 이 상태에서 균등가중
한 개를 최종 점수로 고르면 분석 결과보다 정책 선택이 순위를 더 많이 결정하게
됩니다. 따라서 전체 순위는 없애는 것이 아니라, 네 시나리오의 중앙적 위치와
변동범위를 함께 보여주는 `통합 검토대기열`로 제한합니다.

전체 순위는 부처·회계·재정수단이 다른 사업의 효과성을 직접 비교한 결과가
아닙니다. 전 부처에서 어떤 후보를 먼저 확인할지 정하는 작업 순서입니다.

## 3개 부처 193행의 범위와 4개 부처 통합 점검

193행은 현재 저장된 4개 부처 통합 결과가 아니라 다음 **3개 부처의
프로그램-연도-회계유형 순위 적격 후보**를 합친 수입니다. 시나리오 점수표
772행은 이 후보 193개에 네 가중치 시나리오를 각각 적용한 결과입니다.

| 부처 | 순위 적격 후보행 |
|---|---:|
| 고용노동부(019) | 41 |
| 보건복지부(075) | 81 |
| 과학기술정보통신부(162) | 71 |
| 합계 | 193 |

중소벤처기업부(102)는 `mss_same_year_budget_check`와
`mss_priority_scenarios`에 별도 파일럿으로 남아 있습니다. 중기부 결합표는
3개 부처 확장 전 스키마여서 현재 분석키인 분야·부문이 없고, 대시보드도
`three_ministry_priority_scenarios`만 읽습니다. 따라서 현재 상태는
4개 부처 통합 마스터가 아닙니다.

현재 코드와 최신 재정 마스터로 중기부를 임시 재생성한 뒤 4개 부처를 합친
검증 결과는 다음과 같습니다.

| 검증항목 | 4개 부처 임시 통합 결과 |
|---|---:|
| 전체 프로그램-연도-회계유형 후보 | 412행 |
| 네 시나리오 순위 적격 후보 | 235행 |
| 시나리오 점수 | 940행(235×4) |
| 결합키 중복 | 0행 |
| 중기부 전체/순위 적격 후보 | 65/42행 |

기존 중기부 점수표와 3개 부처 점수표를 단순 연결해서는 안 됩니다. 재정영향
구성요소는 연도별 전체 후보 안에서 예산 백분위를 다시 계산하고 전체 순위도
새 모집단에서 다시 산출하기 때문입니다. 실제 임시 통합에서 기존 3개 부처
시나리오 점수 772행이 모두 변했습니다. 따라서 중기부 최신 재생성, 4개 부처
후보 결합, 구성요소·전체순위 재계산을 한 번에 수행해야 합니다.

2026-07-31 현재 후보의 세부사업 참조와 M3 재정신호를 대조한 결과는 다음과
같습니다. 아래 첫 표는 현재 저장된 3개 부처 193행 결과입니다.

| 점검항목 | 결과 |
|---|---:|
| 원천 세부사업-연도 참조 | 2,175행 |
| 분석 모집단과 정확히 연결 | 2,050행(94.25%) |
| 부처·연도·프로그램·회계유형 불일치 | 0행 |
| 연결된 고유 종단 세부사업 | 1,050개 |
| 자체 재정신호가 있는 세부사업-연도 | 1,124행 |
| 자체 재정신호가 하나 이상 있는 프로그램 후보 | 178/193행 |
| 자체 재정신호가 없는 프로그램 후보 | 15/193행 |

연결되지 않은 125개 참조는 연결 오류가 아닙니다. `source_project_ids`는 원천
전체를 보존하지만 M3 재정신호는 분석 모집단만 포함하기 때문에 생긴 차이이며,
193행의 `account_analysis_included_project_count`와 실제 연결 건수는 모두
일치했습니다.

따라서 **프로그램 상위신호 아래에서 자체 예산·집행·사업구조 신호가 있는
세부사업을 점검후보로 제시하는 것**은 가능합니다. 반면 현재 성과지표는
프로그램 단위이므로, 프로그램 성과점수를 세부사업에 배분한
`세부사업 성과+재정 종합점수`는 만들 수 없습니다. 최종 후보는 다음 두 단계로
운영합니다.

1. 프로그램 단위 성과·재정 신호로 검토할 프로그램을 좁힙니다.
2. 선택된 프로그램 안에서 세부사업 자체의 재정신호로 세부사업 검토순서를
   제시하고, 프로그램 성과는 상위 맥락으로만 표시합니다.

자체 재정신호가 없는 15개 프로그램 후보는 세부사업을 억지로 순위화하지 않고
프로그램 수준 검토 또는 사업설명자료·평가자료 보강 대상으로 남깁니다.

4개 부처 임시 통합 235행에서는 원천 세부사업-연도 참조 2,471행 중
2,338행(94.62%)이 분석 모집단과 연결됐고, 1,288행이 자체 재정신호를
가졌습니다. 세부사업 자체 신호가 하나 이상 있는 후보는 215/235행입니다.
따라서 중기부를 포함해도 2단계 세부사업 드릴다운은 구현 가능하지만,
영구 통합 산출물과 대시보드 연결을 먼저 완료해야 합니다.

## 기존 재정사업 성과평가 레퍼런스

### 1. 2024년 재정사업 자율평가 구조

국회예산정책처가 인용한 2024년 재정사업 자율평가 지침은 세부사업 단위에서
다음 100점 구조를 사용했습니다.

| 평가항목 | 배점 |
|---|---:|
| 사업계획의 적정성 | 10 |
| 집행의 효율성 | 30 |
| 성과 달성도 | 40 |
| 성과 우수성 | 10 |
| 환류 및 개선노력 | 10 |
| 부처별 가감점 | ±3 이내 |

평가항목과 총점은 있었지만 세부 기준과 등급 간격은 부처별로 조정할 수
있었습니다. 실제 2020회계연도 국방부 사례에서는 73.72~77.35점인 사업도
`미흡`으로 분류됐습니다. 따라서 과거 제도도 `80점 미만이면 전국 공통 위험`
같은 절대 기준으로 운영된 것은 아닙니다.

- [국회예산정책처의 2020회계연도 국방부 항목별 점수 사례](https://www.nabo.go.kr/board/file/down.do?fid=33316781)

### 2. 2026년 통합 재정사업 성과평가 구조

현행 통합평가는 숫자 총점보다 다음 네 평가축과 사람의 종합판단을 사용합니다.

1. 재정사업 필요성
2. 사업계획의 적정성
3. 집행 효율성
4. 성과달성도 및 우수성

결과도 점수구간이 아니라 `정상추진`, `사업개선`, `감액`, `폐지`, `통합`의
다섯 범주입니다. 외부전문가 153명이 15개 분야를 나누어 검토하고,
서면평가-대면평가-쟁점사업평가의 3단계에서 소관부처 의견을 들었습니다.

이 구조에서 프로젝트에 적용할 핵심은 `자동 점수 → 바로 판정`이 아니라
`정량 선별 → 근거 확인 → 사람 검토 → 설명 가능한 상태 분류` 순서입니다.

- [기획예산처 2026년 통합 재정사업 성과평가 결과와 평가항목](https://www.mpb.go.kr/web/main/bbs/b_0001/1791)
- [국가재정법 시행령 제39조의3 통합재정사업성과평가](https://law.go.kr/LSW/lsLinkCommonInfo.do?lspttninfSeq=172167)
- [열린재정의 성과계획-집행-성과평가-환류 구조](https://www.openfiscaldata.go.kr/op/ko/br/UOPKOBRA01)

### 3. 해외 보조 레퍼런스

미국 OMB의 PART는 평가영역별 0~100점을 제공하면서도 하나의 가중 총점이
과도한 정밀성을 암시할 수 있다고 경고하고, 성과지표·기준선·성과자료가 없으면
총점과 무관하게 `Results Not Demonstrated`로 분리했습니다. OECD/JRC도
복합지표를 순위에 사용할 때 가중치·결측·정규화 선택에 대한 민감도 분석과
불확실성 공개를 요구합니다.

- [미국 OMB PART의 0~100점·등급·자료부족 예외 구조](https://obamawhitehouse.archives.gov/sites/default/files/omb/assets/omb/expectmore/part.html)
- [OECD/JRC 복합지표 작성 지침](https://www.oecd.org/en/publications/handbook-on-constructing-composite-indicators-methodology-and-user-guide_9789264043466-en.html)

## 프로젝트 적용안

### 왜 공식평가를 그대로 복제하지 않는가

공식평가를 그대로 복제하지 않는 이유는 전문가가 없어서가 아니라, **이
프로젝트와 공식평가의 역할·평가단위·보유근거가 다르기 때문**입니다.

| 구분 | 공식 통합평가 | 이 프로젝트 |
|---|---|---|
| 의사결정 | 정상추진·개선·감액·폐지·통합 등 예산환류 | 전문가가 먼저 볼 사업과 근거의 순서 제시 |
| 평가주체 | 권한과 추가자료를 가진 외부전문가 평가단 | 공개자료를 처리하는 분석 파이프라인 |
| 평가단위 | 세부사업 | 성과는 프로그램, 재정 원인은 세부사업 드릴다운 |
| 근거범위 | 필요성·대체수단·수혜자·전달체계·정책기여 등 정성자료 포함 | 목표·실적·예산·집행·사업구조 중심 |
| 결과형태 | 사람의 종합판단에 따른 5개 처분 범주 | 재현 가능한 점수·순위·근거검수 상태 |
| 검증절차 | 서면-대면-쟁점사업평가와 부처 소명 | 데이터 품질·가중치 민감도·순위 안정성·원문 대조 |

그대로 복제하면 다음 문제가 생깁니다.

1. **없는 자료를 점수로 만들어야 합니다.** 사업 필요성, 민간·지자체 대체
   가능성, 유사중복, 수혜자 범위, 전달체계, 국민 체감도는 현재 구조화
   데이터에 없습니다. 이를 0점으로 넣으면 `자료 없음`을 `사업 부실`로
   오판하게 됩니다.
2. **평가단위가 어긋납니다.** 공식평가는 세부사업 단위지만 현재 성과지표는
   프로그램 단위입니다. 공식 양식을 그대로 적용하려면 프로그램 성과를
   세부사업 성과로 임의 귀속하게 되어 프로젝트의 분석 원칙을 위반합니다.
3. **공식 처분에는 분석 밖의 권한과 절차가 필요합니다.** 감액·폐지·통합은
   사업 필요성, 정책 우선순위, 부처 소명과 추가자료를 종합한 판단입니다.
   공개 정량자료만으로 같은 명칭을 자동 부여할 근거가 없습니다.
4. **과거 100점도 고정 절대기준이 아니었습니다.** 부처별 세부기준을 조정할
   수 있었고 73.72~77.35점도 `미흡`으로 분류된 사례가 있습니다. 공식 배점만
   복사해 `80점 이상 위험`으로 바꾸면 원 제도의 의미와도 달라집니다.
5. **현행 공식평가에는 고정 총점 순위가 없습니다.** 2026년 통합평가는
   4대 평가축과 5개 결과범주를 사용하므로, 이를 그대로 가져오면 사용자가
   원하는 전체·부처별 검토순위와 점수구간을 만들 수 없습니다.

### 전문가가 검토한다면 프로젝트는 무엇을 해야 하는가

공식평가 구조를 버리지 않고 다음 두 단계로 역할을 분리합니다.

#### 1단계: 자동 선별

- 193개 순위 적격 후보를 같은 규칙으로 반복 계산
- 전체 및 부처별 점검 우선순위 제공
- 성과미달, 집행설명필요, 성과·예산 불일치, 재정영향의 신호 분해
- 가중치 시나리오별 순위범위와 안정성 공개
- 원문·조인·핵심값이 불확실하면 `데이터 먼저 확인`으로 분리

이 단계의 질문은 `어떤 사업이 나쁜가`가 아니라
`전문가가 어디부터 어떤 이유로 봐야 하는가`입니다.

#### 2단계: 전문가 검토

자동 선별 결과와 원문근거를 보고 다음 공식평가 축을 직접 확인합니다.

- 재정사업 필요성
- 사업계획의 적정성
- 집행 효율성
- 성과달성도 및 우수성

전문가 검토 화면에는 축별 판단, 근거 문서·페이지, 판단 메모, 추가자료 요청,
최종 검토상태를 기록합니다. 감액·폐지·통합 같은 처분성 결과가 필요하다면
이 단계에서만 입력하고 자동점수로 생성하지 않습니다.

따라서 이 프로젝트의 추가가치는 전문가 판단을 대체하는 점수가 아니라
`후보 축소 → 근거 묶음 → 일관된 검토양식 → 판단 기록`을 제공하는 것입니다.

### 공식 평가항목별 현재 데이터 충족도

| 공식 평가항목 | 공식평가에 필요한 근거 | 현재 자동화 가능 | 처리방식 |
|---|---|---|---|
| 재정사업 필요성 | 목적 타당성, 재정지원 필요, 다른 정책수단, 민간·지자체 대체, 유사중복 | 거의 불가 | 전문가 전용 |
| 사업계획 적정성 | 상위계획 연계, 사업내용, 수혜자 범위, 재정수요와 지원규모 | 일부 프로그램 목표만 보유 | 원문·전문가 검토 |
| 집행 효율성 | 실집행, 추진·전달체계, 부정수급 관리, 외부지적 환류 | 예산·집행·반복 집행신호 가능 | 정량선별 후 전문가 보완 |
| 성과달성도 | 목표·실적·달성 여부 | 가능하나 원문검수 필요 | 정량선별 |
| 성과 우수성 | 정책기여, 국민 체감도·만족도, 질적 우수성 | 불가 | 전문가 전용 |
| 공식 결과범주 | 모든 축의 종합판단과 부처 소명 | 불가 | 전문가 검토 후 입력 |

현재 순위모형의 네 구성요소가 모두 존재하는 후보는 193행이지만, 이것은
공식평가 네 축이 완전하다는 뜻이 아닙니다. 원문 근거가 모두 자동 강근거인
후보는 89행이고, 혼합 26행, 전부 필수검수 대상 78행입니다. 정량 구성요소의
완전성과 공식평가 근거의 완전성을 구분해야 합니다.

### 왜 이 형식이 프로젝트에 맞는가

1. **최종 사용방식과 맞습니다.** 전체 검토대기열, 부처별 순위, 점수구간,
   사업별 근거카드라는 사용자의 대시보드 목표를 직접 지원합니다.
2. **프로그램-세부사업 계층을 보존합니다.** 성과는 프로그램에서 신호를
   만들고, 세부사업은 예산·집행 원인을 확인하는 드릴다운으로 사용합니다.
3. **없는 값을 0점으로 만들지 않습니다.** 데이터 부족은 별도 상태로
   분리하고 공식 정성항목은 전문가에게 남깁니다.
4. **점수의 자의성을 드러냅니다.** 네 가중치 시나리오와 순위범위를 함께
   제시하여 한 가중치가 결론을 지배하는지 확인할 수 있습니다.
5. **검토량을 실제로 줄입니다.** 193행 전체를 같은 깊이로 보지 않고,
   잠정 80점 이상 38행, 이 중 부처 내부 시나리오 안정 후보 33행부터
   확인할 수 있습니다.
6. **공식평가로 확장할 수 있습니다.** 향후 사업설명자료와 전문가 판단이
   들어오면 2단계 검토표에 공식 4대축을 추가할 수 있고 1단계 순위의
   재현성은 그대로 유지됩니다.

전체 순위는 부처·회계·재정수단이 다른 사업의 절대적 효과성 순위가 아니라
검토 자원을 배분하는 통합 대기열입니다. 실제 판단은 비교집단 정보와 부처별
순위, 공식 평가축 검토를 함께 보고 수행합니다. 이는 현행 공식평가가 15개
분야별 분과를 두고 전문가 토론·조정을 거치는 구조와도 방향이 같습니다.

### 평가축 매핑

| 기존 평가 구조 | 현재 데이터로 가능한 범위 | 적용 |
|---|---|---|
| 재정사업 필요성 | 자동 판단 불가 | 원문·전문가 검토항목으로 보류 |
| 사업계획의 적정성 | 일부 성과목표·지표 구조만 확인 가능 | 점수에 넣지 않고 검수카드에 표시 |
| 집행 효율성 | 집행률, 반복 저집행, 연말집중 등 | 정량 점수축 |
| 성과 달성도 | 목표·실적·달성 여부 | 정량 점수축 |
| 성과 우수성 | 단순 달성률만으로 판단 불가 | 외부 근거가 생길 때까지 보류 |
| 환류 및 개선노력 | 후속예산 변화 일부만 관측 | 인과판정 없이 불일치 신호로 표시 |
| 재정영향 | 과거 공식 평가의 문제점수는 아님 | 검토 파급효과와 동순위 순서 |

현재 데이터는 공식 평가 네 축 전체를 재현하지 못합니다. 특히 사업 필요성,
계획 적정성, 전달체계, 성과 우수성은 공식 사업설명자료와 사람 판단이
필요합니다. 따라서 화면 이름도 `성과평가 재현`이 아니라
`성과·재정 기반 점검 우선순위`로 유지합니다.

### 점수와 순위

```text
전체 점검 우선순위 점수
= 100 × 네 시나리오 전체 순위백분위의 중앙값

부처별 점검 우선순위 점수
= 100 × 네 시나리오 부처 내부 순위백분위의 중앙값
```

중앙값을 쓰는 이유는 한 시나리오가 유난히 높거나 낮을 때 그 한 관점이
통합점수를 지배하지 않게 하기 위해서입니다. 시나리오별 최저·최고 순위와
순위범위는 점수 옆에 그대로 공개합니다.

현재 193행에 적용했을 때의 잠정 구간은 다음과 같습니다.

| 표시 기준 | 전체 비교 | 부처 내부 비교 |
|---|---:|---:|
| 90점 이상 `집중점검 신호` | 20행 | 19행 |
| 80점 이상 `우선점검 신호` | 38행 | 38행 |
| 80점 미만 | 155행 | 155행 |

80점은 상위 약 20%, 90점은 상위 약 10%가 되도록 만든 상대점수이므로
발표에서 의미를 설명하기 쉽습니다. 다만 모집단이 바뀌면 같은 사업의 점수도
달라질 수 있습니다. 현재는 확정 정책이 아니라 3개 부처 MVP의 잠정값입니다.

### 점수와 별도로 유지할 가드레일

- `데이터 먼저 확인`: 핵심값·연결·원문 근거가 부족한 경우 점수보다 우선
- `시나리오 안정`: 80점 이상이면서 3개 이상 시나리오에서 상위 20%
- `가중치 민감`: 점수는 높지만 시나리오 합의가 부족
- `반복`: 동일 프로그램이 2개 이상 연도에서 반복
- `근거검수 필요`: 연결된 성과지표 원문 확인이 남음

점수만으로 `감액`, `폐지`, `통합`을 붙이지 않습니다. 이 세 범주는 현행
공식평가에서도 필요성·계획·전달체계·성과 근거를 사람이 종합 검토한 뒤
부여하는 결과이기 때문입니다.

## 현재 원문 근거 상태

순위 적격 193행을 해당 성과지표의 PDF 대조 상태로 나누면 다음과 같습니다.

| 원문 근거 상태 | 후보행 |
|---|---:|
| 모든 지표가 자동 강근거 | 89 |
| 강근거와 필수 검수 지표가 혼합 | 26 |
| 모든 지표가 필수 검수 대상 | 78 |

PDF 검수 완료를 193행 전체의 선행조건으로 두면 분석이 멈춥니다. 반대로 검수
없이 순위를 확정하면 근거가 약합니다. 따라서 후보를 먼저 좁힌 뒤 그 후보의
원문만 검수하는 방식을 사용합니다.

## 정책 후보별 영향

부처 내부 순위 백분위를 이용해 실제 193행을 비교한 결과입니다. 동률은 그대로
보존했습니다.

수치 근거표와 권장안의 30개 원문검수 목록은 다음 위치에 생성했습니다.

```text
data/analytics/priority_policy_decision_support/policy_option_summary.csv
data/analytics/priority_policy_decision_support/recommended_source_review_queue.csv
```

| 정책 후보 | 후보행 | 고유 프로그램 | 고용부 | 복지부 | 과기부 | 연결 성과지표 | 이 중 필수 원문검수 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 상위 10%·3/4 시나리오 | 18 | 13 | 5 | 6 | 7 | 32 | 18 |
| 상위 20%·3/4 시나리오 | 33 | 23 | 7 | 15 | 11 | 55 | 30 |
| 상위 20%·2/4 시나리오 | 43 | 27 | 10 | 18 | 15 | 64 | 33 |
| 상위 20%·4/4 시나리오 | 11 | 9 | 3 | 1 | 7 | 22 | 10 |

### 선택지 A: 상위 10%·3/4만 사용

장점:

- 18행·13개 프로그램으로 가장 간결합니다.
- 필수 원문검수가 18개 지표라 빠르게 끝낼 수 있습니다.

단점:

- 상위 경계의 작은 순위변화에 민감합니다.
- 탐색 단계에서 놓치는 후보가 생길 수 있습니다.

### 선택지 B: 상위 20%·3/4를 우선 검토군으로 사용

장점:

- 세 시나리오 이상에서 반복되는 후보만 남겨 가중치 의존성을 줄입니다.
- 33행·23개 프로그램으로 검토 가능한 크기입니다.
- 필수 원문검수는 201행 전체가 아니라 30개 지표입니다.

단점:

- 최종 발표 사례로는 아직 많습니다.
- 부처별 후보 수가 7·15·11행으로 같지 않습니다.

### 선택지 C: 상위 20%·2/4를 사용

장점:

- 한 가지 관점에서만 강한 후보도 넓게 포착합니다.

단점:

- 가중치 의존 후보가 많이 포함됩니다.
- 정책 설명력이 B보다 약합니다.

### 선택지 D: 상위 20%·4/4만 사용

장점:

- 네 관점 모두에서 높은 후보만 남습니다.

단점:

- 복지부가 1행으로 줄어 부처 간 대표성이 크게 흔들립니다.
- 너무 보수적이라 사례 다양성을 잃습니다.

## 권장 정책 구조

### 1. 순위 진입 가드레일

다음 조건을 모두 만족해야 복수 시나리오 비교에 들어갑니다.

- 프로그램 매칭과 재정 연결이 분석 가능
- 네 시나리오 구성요소가 모두 존재
- 결측값을 0으로 대체하지 않음
- 정책사업 순위 범위에 포함

원문 검수가 덜 끝난 후보는 삭제하지 않고 `근거검수 필요` 배지를 붙입니다.

### 2. 주 지표

```text
네 시나리오 순위백분위 중앙값 × 100
```

전체 비교와 부처 내부 비교를 각각 계산합니다. 네 시나리오는 균등가중,
성과중심, 집행중심, 재정영향 보정입니다.

### 3. 점수 구간

- 90점 이상: `집중점검 신호`
- 80점 이상 90점 미만: `우선점검 신호`
- 80점 미만: 일반 검토대기열

80점 이상은 현재 193행에서 전체 기준과 부처 내부 기준 모두 38행입니다.
90점 이상은 전체 기준 20행, 부처 내부 기준 19행입니다.

### 4. 시나리오 합의도

- 80점 이상이고 3개 이상 시나리오에서 상위 20%: `시나리오 안정`
- 80점 이상이지만 상위 20% 진입이 2개 이하: `가중치 민감`

기존 `부처 내부 상위 20%·3/4` 정책 후보 33행은 부처 내부 80점 이상이면서
시나리오 안정 조건을 충족하는 집단과 같습니다. 발표 사례는 이 집단의
원문검수 완료 후보에서 먼저 고릅니다.

### 5. 보조 지표

- 동일 프로그램의 2개 이상 연도 반복 여부
- 시나리오별 순위 범위와 표준편차
- 신호 유형: 성과, 집행, 성과·예산 불일치, 구조·회계 맥락

상위 20%·3/4 우선 검토군의 23개 프로그램 중 6개는 2개 이상 연도에서
반복됩니다. 반복성은 등급을 자동 올리는 점수가 아니라 같은 등급 안에서 먼저
볼 근거로 사용합니다.

### 6. 사업규모 가드레일

본예산 규모는 위험 점수로 해석하지 않습니다. 같은 합의도와 같은 반복성을 가진
후보 사이에서 검토 파급효과를 설명하는 보조정보로만 사용합니다.

### 7. 원문검수 가드레일

- 우선 검토군 33행과 연결된 지표 55개 중 필수 검수 30개를 먼저 확인합니다.
- 자동 강근거 25개는 우선 검토군 단계에서는 유지하되 발표 사례로 선택되면 확인합니다.
- `수정 필요`는 수정 오버레이 반영 전까지 확정 후보로 표시하지 않습니다.
- `현재 문서로 확인 불가`는 성과 근거를 사용하는 순위에서 제외하고 재정 신호만 별도 표시합니다.

## 대시보드 표시 권장안

기본 화면은 `전체 기준`과 `부처별 기준`을 전환할 수 있는 하나의 표로
구성합니다.

| 표시 | 의미 |
|---|---|
| 점검 우선순위 점수 | 선택한 비교집단에서 네 시나리오 순위백분위 중앙값 |
| 전체 순위 | 193행 전체 비교점수의 내림차순 |
| 부처별 순위 | 선택 부처 내부 비교점수의 내림차순 |
| 우선점검 신호 | 선택한 기준에서 80점 이상 |
| 집중점검 신호 | 선택한 기준에서 90점 이상 |
| 시나리오 안정 | 3개 이상 시나리오에서 상위 20% |
| 반복 | 동일 프로그램이 2개 이상 연도에 포함 |
| 가중치 민감 | 높은 점수에 비해 시나리오 합의가 부족하거나 순위범위가 큼 |
| 근거검수 필요 | 연결 지표 중 필수 PDF 검수행 존재 |
| 데이터 먼저 확인 | 프로그램·재정 연결 또는 핵심값 검증 필요 |

전체 순위와 부처별 순위는 모두 제공하지만, 화면 상단에 현재 비교기준을
명시합니다. 전체 순위는 전 부처 검토대기열, 부처별 순위는 부처 내부
검토순서로 설명합니다.

## 사용자 결정이 필요한 항목

1. 80점·90점 구간을 3개 부처 MVP의 잠정 기준으로 채택할지
2. `시나리오 안정`을 최종 우선 검토군의 추가 조건으로 사용할지
3. 같은 프로그램의 2개 이상 연도 반복을 동순위 우선조건으로 사용할지
4. `수정 필요` 행의 정답을 분석 마스터에 반영하는 수정 오버레이를 다음 작업으로 만들지

권장안은 80점·90점을 우선 화면에 적용하되 `잠정`이라고 표시하고,
`시나리오 안정`과 원문근거 상태를 함께 보여주는 것입니다. 멘토 확인과
상위 사례 원문검토 전까지는 설정파일과 최종 발표 결론에 고정하지 않습니다.
