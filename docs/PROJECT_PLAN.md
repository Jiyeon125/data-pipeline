# 재정사업 성과·집행·예산 연계 분석 프로젝트 계획

> 목적·사용자·의사결정·최종 분석단위·확장계약과 2026-08-03 동결범위는
> `docs/PROJECT_POLARIS.md`를 최상위 기준으로 사용합니다. 두 문서가
> 충돌하면 구현을 멈추고 폴라리스의 결정을 먼저 확인합니다.

## 1. 목적

공개 재정데이터와 성과관리 자료를 프로그램·세부사업 계층에 맞게 연결하여
성과, 예산, 집행, 결산과 후속 예산 변화를 통합 분석합니다. 결과는 자동
삭감·폐지 판정이 아니라 원문 검토와 점검 우선순위를 지원하는 참고자료입니다.

## 2. 대상

- 현재 경진대회 실증 부처: `019`, `075`, `102`, `162`
- 품질 정리 후 추가 검토 부처: `101`
- 최종 구조는 부처 수와 이름을 코드에 고정하지 않는 N개 부처 처리 방식
- 연도: 2022~2025년
- 코드값은 문자열로 관리하며 앞자리 0을 보존합니다.
- 프로그램-연도, 세부사업-연도, 세부사업-월, 성과지표-연도를 분리합니다.

## 3. 구현 경계

- 원본 파일과 원본 금액은 수정하지 않습니다.
- 금액유형과 출처를 분리하고 파생값에 산식·결측사유를 남깁니다.
- 구조적 결측은 0이나 전년값으로 보간하지 않습니다.
- 프로그램 성과를 세부사업 성과로 임의 귀속하지 않습니다.
- LLM은 성과문서의 확인 가능한 값 추출에만 사용하며, API 키가 없거나
  비LLM 작업을 수행할 때는 호출하지 않습니다.
- 2026-08-03 선택형 비전 v3의 실패사례 3건 회귀검증 결과는 고도화 체크포인트로
  동결합니다. 현재 대회 MVP는 수기 검증 성과데이터로 분석을 진행하고, 34건 재검증·
  230쪽 확대·자동승격은 폐기하지 않고 후속 고도화 범위로 보류합니다.
- 재정수단·사업관계 후보는 규칙으로 생성할 수 있지만 불충분한 근거를 자동
  확정하지 않습니다.

## 4. 모집단 사용 정책

### broad_population

- 전체 재정구조
- 사업 수와 예산 규모
- 회계·재정수단 분포
- 일반 기술통계

### core_financial_population

- 본예산·예산현액·지출·결산 분석
- 집행률 분석
- 연도별 재정 추세
- 프로그램-연도 집계

### strict_ranking_population

- 비교집단 내부 점검 우선순위 산정에만 사용
- 일반 재정규모와 전체 사업 현황 설명에는 사용하지 않음
- 비교집단 크기 5 미만은 병합하지 않고 순위 제한

strict 모집단 대표성 경고 집단:

- 고용노동부 기금 2022~2025년
- 과학기술정보통신부 기금 2024년

## 5. 사업 연속성과 구조적 변화

인접연도 관계는 다음 순서로 판별합니다.

1. 동일 세부사업코드
2. 동일 프로그램·단위사업·세부사업 계층
3. 부처·회계·세부사업명 정확 일치
4. 정규화 명칭 유사도
5. 동일 프로그램·단위사업 안의 명칭 유사도
6. 일대다 분할 후보
7. 다대일 통합 후보
8. 부처 변경 이관 후보

일대일 동일 코드처럼 강한 근거만 자동 확정합니다. 명칭 유사도만으로
`MERGED`, `SPLIT`, `TRANSFERRED`를 확정하지 않습니다.

신규·종료·이관·통합·분할·연속성 미확정 사업은 일반 예산 증감률 계산에서
제외하고 사유를 별도 필드로 기록합니다.

관측창 경계 자체는 실제 신규·종료 근거가 아닙니다. 2022년 이전 자료가 없는
행은 `OBSERVATION_START`/`LEFT_CENSORED`, 2025년 이후 자료가 없는 계속관측 행은
`OBSERVATION_END`/`RIGHT_CENSORED`로 관리합니다. 경계만이 원인인 관계는
`INFORMATIONAL`이며 수기검토 대상에 포함하지 않습니다.

## 6. 프로그램 집계

- core 모집단을 사용합니다.
- 일반·특별·책임운영기관회계는 결산 지출액 합계/결산 예산현액 합계로
  집행률을 계산합니다.
- 기금은 확인된 지출액 합계/확인된 지출계획현액 합계로 계산합니다.
- 회계유형이 섞이면 회계별 적정 분자를 분모와 함께 합산한 뒤 총비율을
  계산합니다.
- 일부 세부사업만 연결된 `PARTIAL` 또는 `UNMATCHED` 프로그램은 부분 집행률을
  전체값처럼 제시하지 않습니다.

## 7. 주요 단계

1. 원본 수집과 무변경 보존
2. 예산·월별 집행·결산 정규화
3. financial v1 품질검증
4. 사업분류 및 분석 모집단 확정
5. 모집단 민감도·대표성 검증
6. 사업계보와 financial v2 구축
7. 프로그램-연도 집계
8. 성과문서 구조화 및 성과 연계
9. 파생변수·점검 우선순위·민감도 분석
10. 대시보드·보고서·사례카드 작성

## 8. 검증 원칙

- 입력과 출력 행 수 및 기본키 중복을 검증합니다.
- 원본 금액 변경 여부를 셀 단위로 확인합니다.
- 분석 포함·제외와 결측사유를 기록합니다.
- 모든 결과를 원천 파일 또는 이전 단계 행까지 추적할 수 있게 합니다.
- pytest와 Ruff 결과, 실제 행 수·금액·수기검토 수를 `WORK_LOG.md`에 남깁니다.

## 9. 명목·실질 예산환류

- 명목 T+1·T+2 본예산 증감률은 원본 분석값으로 보존합니다.
- 2022~2024 완결 구간에는 KOSIS가 제공하고 한국은행 국민계정을 원출처로 하는
  GDP 디플레이터(2020=100)를 적용해 실질 증감률을 별도 민감도 변수로 생성합니다.
- 명목 증가가 실질 비증가로 바뀌는 행은 `물가보정 민감`으로 표시하되 기존
  점검후보를 자동 삭제하거나 실질값으로 대체하지 않습니다.
- 특정 사업의 장비비·공사비·인건비 물가지수가 필요한지는 사례 검토에서 판단합니다.
- 2025가 포함되는 T+1·T+2는 최신 잠정계열 채택 결정 전까지 현재 실질 민감도에서
  제외합니다.
