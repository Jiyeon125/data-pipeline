# 점검 우선순위 파생변수·수학적 모델링 설계

작성일: 2026-07-31  
상태: **구현 전 권장 설계** — 아래 임계값과 분류는 검증 후보이며 확정 정책이 아닙니다.

## 1. 결론

이 프로젝트의 우선순위는 하나의 가중합 점수보다 다음 구조가 더 타당합니다.

```text
데이터 사용 가능 여부
→ 비교 가능한 사업끼리 층화
→ 성과·집행·예산환류·예산구조 신호를 각각 계산
→ 반복 신호와 복수 신호를 우선
→ 같은 점검유형 안에서 신호 강도와 예산 영향규모로 정렬
→ 원문·전문가 검토
```

핵심은 `점수 = 사업의 좋고 나쁨`이 아니라 `어떤 근거를 먼저 확인할지`입니다.
성과, 집행, 예산환류, 예산구조는 서로 대체할 수 없으므로 기본 화면에서 합산하지
않습니다. 가중합은 결과가 가중치에 얼마나 흔들리는지 보는 민감도 분석에만 남깁니다.

현재 4개 부처 자료에는 다음 기반이 있습니다.

- 성과지표 424행과 원문 근거
- 프로그램·연도·회계유형 후보 412행
- 세부사업 드릴다운 3,286행
- 프로그램 성과 미달, 집행, T+1·T+2 예산환류, 세부사업 재정 신호

반면 성과지표 유형, 기대 성과시차, 사업 전달방식, 법정의무성, 세목 수준의 목적 외
지출, 융자 회수·순재정부담은 아직 확정 데이터가 아닙니다. 이 값들은 아래와 같이
**연속 파생변수**, **비교집단 변수**, **전문가 근거 변수**로 나눠 보강해야 합니다.

실제 스키마로 계산 가능성을 점검한 결과는 다음과 같습니다.

| 항목 | 현재 계산 가능한 관측 | 판단 |
|---|---:|---|
| 공식 달성률 동년도 분석 | 419/424 지표 | 바로 파생변수 생성 가능 |
| 프로그램·회계유형 집행률 | 401/412 후보 | 바로 생성 가능, 11행은 별도 적격 처리 |
| 프로그램 전체 T+1 증감 | 107/412 후보 | 가능하지만 완결 코호트만 사용 |
| 프로그램 전체 T+2 증감 | 69/412 후보 | 가능하지만 표본 수를 반드시 표시 |
| 전년도 실적–당해 목표 동일명 연속쌍 | 156쌍 | 목표 도전성 후보, 지표 연속성 검증 필요 |
| 문서화된 목표변경 구조필드 | 63행 | 현재 중기부 중심, 타 부처 확장 필요 |

따라서 성과·집행·명목 환류는 즉시 고도화할 수 있고, 목표 도전성은 조건부로 가능하며,
사업성격과 전문가 판단 변수는 원문 구조화 모듈이 먼저 필요합니다.

## 2. 공식 성과평가에서 가져올 것과 가져오지 않을 것

[열린재정의 성과관리제도](https://www.openfiscaldata.go.kr/op/ko/br/UOPKOBRA01)는
프로그램 목표와 성과지표를 사전에 설정하고, 예산 배분·집행, 성과 측정·평가,
공표·환류로 이어지는 순환구조를 사용합니다. 국가재정법은 지표가 명확하고 구체적이며
객관적·적시적·결과지향적이어야 하고, 예산사업과 성과계획의 내용·비용이 대응하도록
요구합니다. [국가재정법 제85조의6](https://law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1014813007)

2026년 통합평가는 재정성과위원회 심의를 거쳐 확정됐고, 기획예산처도 개별 사업의
판정을 집행 적정성과 재정지원 성과 등을 종합적으로 고려한 결과라고 설명합니다.
[2026년 통합평가 결과](https://www.mpb.go.kr/web/main/bbs/b_0001/1791),
[2026-07-01 보도설명](https://www.mpb.go.kr/web/main/bbs/b_0002/2084)

따라서 공식 평가에서 가져올 것은 다음 네 가지입니다.

1. 계획, 집행, 성과, 환류를 분리해서 봅니다.
2. 사업 필요성·계획 적정성처럼 숫자만으로 판정할 수 없는 영역을 남깁니다.
3. 예산 조정 결론은 사람 검토 뒤에 둡니다.
4. 공식 평가결과는 정답 라벨이 아니라 외부 타당성 확인용 평가 이벤트로 연결합니다.

가져오지 않을 것은 공식 평가의 결론을 모사한 임의 점수표입니다. 현재 자료만으로
`감액`, `폐지`, `부실`을 재현할 수 없고, 이 프로젝트의 목적도 전문가의 검토 순서를
줄이는 것이기 때문입니다.

또한 현행 시행령은 계획의 적정성과 성과를 평가할 수 있게 하고, 추가 평가 필요,
유사·중복 또는 비효율, 재정지출 급증 등을 심층평가 후보로 둘 수 있게 합니다.
[국가재정법 시행령 제39조의3](https://law.go.kr/LSW/lsLinkCommonInfo.do?lspttninfSeq=172167)
이는 아래의 `계획 품질`, `중복 후보`, `실질 지출 증가` 변수를 점검 후보로 만드는
근거이지, 자동 판정의 근거는 아닙니다.

## 4. 성과 특성

### 4.1 현재 바로 만들 수 있는 값

성과지표 `j`의 공식 달성률을 `r_ij`라고 할 때 프로그램 `i`에 대해 계산합니다.
공식 달성률이 있으면 방향이 낮을수록 좋은 지표도 임의 재계산하지 않습니다.

| 파생변수 | 산식 | 등급 | 해석 |
|---|---|---|---|
| 지표 사용가능률 | `valid_indicator_count / indicator_count` | A | 성과 신호의 대표성 가드레일 |
| 미달지표 비율 | `count(r < 100) / count(valid r)` | A | 미달이 일부인지 전반적인지 |
| 중앙 달성부족 | `median(max(0, 1 - r/100))` | A | 극단값에 덜 흔들리는 전형적 부족 정도 |
| 최악 달성부족 | `max(max(0, 1 - r/100))` | A | 가장 취약한 지표 한 개의 강도 |
| 반복 미달률 | `미달 관측연도 수 / 유효 관측연도 수` | B | 일시적 미달과 반복 미달 분리 |
| 과도달성 비율 | `count(r > c) / count(valid r)` | A | 목표가 느슨하거나 산식 검토가 필요한 후보 |
| 산식검토 비율 | `formula_review_count / valid_indicator_count` | A | 성과 문제가 아니라 데이터·산식 검증 우선 |

`c`는 120%, 150%처럼 임의 확정하지 않고 여러 값으로 민감도를 봅니다. 원 달성률은
보존하고, 순위용으로만 상한 또는 백분위 변환을 검토합니다.

평균 달성률 하나는 사용하지 않습니다. 50%와 150%의 평균이 100%가 되어 미달을
숨길 수 있기 때문입니다. 기본 표현은 `미달비율 + 중앙부족 + 최악부족`의 벡터입니다.

### 4.2 현재 누락된 성과 특성의 수학화

#### 성과지표 유형

`INPUT`, `PROCESS`, `OUTPUT`, `OUTCOME`을 원문 근거로 분류한 뒤 다음 비율을 냅니다.

```text
outcome_share = OUTCOME 지표 수 / 분류완료 지표 수
output_share = OUTPUT 지표 수 / 분류완료 지표 수
input_process_share = (INPUT + PROCESS) / 분류완료 지표 수
type_coverage = 분류완료 지표 수 / 전체 지표 수
```

이 값은 위험점수가 아니라 성과정보의 성격입니다. 결과지표 비율이 낮다고 사업을
나쁘다고 판정하지 않고 `성과지표 재설계 검토`로 보냅니다. 분류 전에는 0점으로
대체하지 않습니다. 등급은 B입니다.

#### 목표 도전성

같은 지표의 전년도 실적 `A_(t-1)`과 당해 목표 `T_t`가 있을 때만 방향을 맞춰 계산합니다.

```text
d(x) = x     (높을수록 좋은 지표)
d(x) = -x    (낮을수록 좋은 지표)

target_challenge_t
= {d(T_t) - d(A_(t-1))} / max(|A_(t-1)|, epsilon)
```

장기 이력이 있으면 과거 실적 개선률 중앙값과 비교합니다.

```text
challenge_above_history
= target_challenge_t - median(direction_adjusted_actual_growth_history)
```

현재 관측창은 짧고 지표 개편도 있으므로 이 값은 바로 순위에 넣지 않습니다. 동일
지표의 연속성이 확인된 경우에만 설명값으로 사용합니다. 등급은 B입니다.

#### 연중 목표 완화

계획서 목표 `T_plan`과 보고서 목표 `T_report`가 다를 때 다음을 계산합니다.

```text
target_relaxation
= max(0, d(T_plan) - d(T_report)) / max(|T_plan|, epsilon)
```

값이 크면 목표 변경 사유 원문을 확인합니다. 정당한 정책변경·외생충격일 수 있으므로
단독 위험점수가 아니라 `목표변경 설명 필요` 신호입니다. 현재 PDF 대조표에 목표변경
필드가 있어 일부는 A, 연속 분석은 B입니다.

#### 성과의 효과성과 효율성

성과 달성은 효과성의 대리값일 뿐 인과효과가 아닙니다. 같은 산출지표가 연도 간
동일하게 유지된 경우에만 단위원가를 계산할 수 있습니다.

```text
real_unit_cost_t = real_expenditure_t / output_t
unit_cost_change_t = real_unit_cost_t / real_unit_cost_(t-1) - 1
```

다른 단위의 지표끼리는 합치지 않습니다. 정책의 순효과는 비교집단, 사전 추세,
수혜자 수준 자료가 있을 때 차분의 차분이나 준실험으로 별도 평가해야 하므로 현재는
X에 가깝고, 단위원가는 조건부 B입니다.

## 5. 집행 특성

회계별로 확인된 분모를 사용합니다. 일반·특별회계는 결산 지출액/결산 예산현액,
기금은 확인된 지출액/지출계획현액입니다.

| 파생변수 | 산식 | 등급 | 역할 |
|---|---|---|---|
| 집행부족 | `max(0, 1 - execution_rate)` | A | 절대적인 미집행 강도 |
| 동료집단 하위꼬리 | `1 - ECDF_g(execution_rate)` | A/B | 같은 성격 사업 안의 상대적 취약성 |
| 반복 저집행률 | `low_execution_year_count / valid_execution_year_count` | A | 일시적·반복적 문제 분리 |
| 4분기 집중 | `(Dec cumulative - Sep cumulative) / Dec cumulative` | A | 연말 집중 설명 필요 |
| 12월 집중 | `(Dec cumulative - Nov cumulative) / Dec cumulative` | A | 12월 단월 집중 설명 필요 |
| 누계감소 횟수 | `count(cumulative_t < cumulative_(t-1))` | A | 환입·조정·자료정정 확인 |
| 이월률 | `carryover / available_budget` | A | 다음 연도 이월 부담 |
| 불용률 | `unused / available_budget` | A | 집행잔액 설명 필요 |

집행률과 불용률은 같은 분모에서 거의 중복될 수 있으므로 동일 점수에 함께 넣지
않습니다. 집행률 100% 초과는 높은 위험점수가 아니라 `분모·조인·회계조정 검증`으로
분류합니다.

고정 기준 80%·90%와 동료집단 하위 10%·20%를 병렬로 보여주고, 하나만 확정하지
않습니다. 반복성과 절대·상대 기준이 동시에 나타날 때 강한 집행 신호로 봅니다.

## 6. 성과–예산 환류 특성

### 6.1 실질 예산증감

동일한 금액유형의 예산 `B`와 디플레이터 `D`를 사용합니다.

```text
real_budget_t = nominal_budget_t / D_t
real_growth_(t,h) = real_budget_(t+h) / real_budget_t - 1
```

T+1과 T+2는 합치지 않습니다. 성과 시차가 확인되지 않으면 두 결과를 모두 보여주고
방향이 같은지 표시합니다.

```text
lag_consistency = sign(real_growth_T1) == sign(real_growth_T2)
```

현재 명목 증감은 A, GDP 디플레이터 연결 뒤 실질 증감은 B입니다.

### 6.2 비대칭 불일치

성과부족 강도 `P`와 실질 예산증가율을 이용해 점검 강도를 만들 수 있습니다.

```text
underperformance_increase_h = P * max(real_growth_h, 0)
```

이 곱은 `성과 미달 + 예산 증가` 유형 안에서만 강도 비교에 씁니다. 성과 양호와 예산
감소는 반대 방향의 위험점수가 아니라 별도 구조변경 맥락입니다.

```text
good_performance_decrease_h
= good_performance_flag * max(-real_growth_h, 0)
```

두 변수를 서로 상쇄하거나 한 점수에 더하지 않습니다.

### 6.3 기대 성과시차

원문과 사업설명자료를 이용해 다음 범주를 근거와 함께 붙입니다.

```text
T, T+1, T+2, LONGER, UNKNOWN
```

시차는 숫자 가점이 아니라 어느 환류 변수를 사용할지 결정하는 스위치입니다.

```text
selected_feedback = feedback_(expected_lag)
```

다년 R&D·시설사업을 즉시 서비스 사업과 같은 T+1 기준으로 벌점화하지 않습니다.
분류는 B/C입니다.

## 7. 예산구조 특성

세부사업 예산 비중을 `s_k`라고 합니다.

| 파생변수 | 산식 | 등급 | 해석 |
|---|---|---|---|
| 상위 1개 비중 | `max(s_k)` | A | 프로그램의 단일사업 의존도 |
| 상위 3개 비중 | `sum(top3 s_k)` | A | 상위 사업 집중도 |
| HHI | `sum(s_k^2)` | A | 전체 분포의 집중도 |
| 정규화 HHI | `(HHI - 1/n) / (1 - 1/n)`, `n >= 2` | A | 사업 수가 다른 프로그램 비교 보정 |
| 집중도 변화 | `normalized_HHI_t - normalized_HHI_(t-1)` | B | 구조가 더 집중되는지 |
| 재배분 거리 | `0.5 * sum(|s_(k,t+1) - s_(k,t)|)` | B | 프로그램 내부 예산구성이 얼마나 바뀌었는지 |
| 분석범위 비중 | `analysis_budget / program_total_budget` | A | 부분합계 대표성 가드레일 |

세부사업이 하나인 프로그램은 HHI가 1인 것이 당연하므로 `단일 구성`으로 표시하고
고위험으로 판정하지 않습니다. 재배분 거리는 0이면 구성 불변, 1이면 완전 교체지만,
사업 코드변경·통합·분할을 먼저 연결해야 합니다.

목·비목 구성이 목적에 맞는지 보려면 세목별 금액과 분류가 추가로 필요합니다.

```text
non_core_share = 목적 외 또는 부대비용으로 확인된 금액 / 전체 예산
```

키워드만으로 목적 외 지출을 확정하지 않고 `분류 후보 → 원문 확인 → 확정` 단계를
거칩니다. 현재는 B/C입니다.

## 8. 사업 성격 때문에 누락된 비교 변수

### 8.1 전달방식과 재정수단

다음 값은 점수가 아니라 비교집단 키입니다.

```text
DIRECT_SERVICE
TRANSFER_OR_SUBSIDY
CONTRIBUTION
LOAN
GUARANTEE
RND_MULTIYEAR
FACILITY_MULTIYEAR
OPERATION
UNKNOWN
```

기본 비교집단 `g`는 다음처럼 구성합니다.

```text
g = 회계연도 × 회계유형 × 검증된 재정수단 × 기대 성과시차
```

표본이 너무 작으면 부처를 먼저 제거해 비교범위를 넓히고, 그래도 작으면 상대순위를
내지 않고 절대 기준과 `소표본` 표시만 둡니다. 구체적인 최소 표본 수는 분포와
민감도를 본 뒤 정합니다.

융자는 일반회계 집행률만으로 평가하지 않습니다. 자료가 확보되면 다음을 별도 계산합니다.

```text
loan_supply_rate = 실제 융자공급액 / 계획 융자공급액
principal_recovery_rate = 회수 원금 / 당기 회수예정 원금
delinquency_rate = 연체잔액 / 대출잔액
net_fiscal_burden
= 이차보전 + 관리비 + 예상신용손실 - 이자·수수료 등 순수입
```

순재정부담은 현금흐름 범위와 부호를 공식 정의한 뒤에만 계산합니다. 현재 자료에는
공급·회수·연체·보증사고 자료가 없어 C입니다.

### 8.2 법정의무성과 조정 가능성

세목 또는 사업 구성요소별로 법정의무·경직성 여부가 확인되면 다음을 계산합니다.

```text
adjustable_budget_share = 조정 가능한 예산 / 전체 예산
mandatory_budget_share = 법정·의무 예산 / 전체 예산
```

금액 구분이 없으면 `MANDATORY`, `MIXED`, `DISCRETIONARY`, `UNKNOWN` 범주로만
사용합니다. 의무지출은 성과가 낮아도 즉시 감액 후보가 아니라 제도개선·전달체계
검토 대상으로 보냅니다. 등급은 C입니다.

### 8.3 사업 생애주기

```text
observed_age = t - first_observed_year + 1
left_censored = first_observed_year == 관측창 시작연도
right_censored = last_observed_year == 관측창 종료연도
```

관측창 경계는 신규·종료로 확정하지 않습니다. `신규`, `확대`, `안정`, `축소`,
`종료 예정`은 공식 근거가 있는 경우에만 비교집단과 기대 시차를 바꾸는 범주값으로
사용합니다. 등급은 A/C 혼합입니다.

## 9. 전문가에게 인사이트는 주지만 자동 점수화하지 않을 값

### 9.1 계획 적정성과 지표 품질

다음은 문서 체크리스트로 구조화할 수 있지만 단일 산식으로 진실을 만들 수 없습니다.

- 사업 목적과 프로그램 목표의 정합성
- 성과지표의 명확성·객관성·적시성·결과지향성
- 목표치 설정 근거의 충분성
- 예산사업 내용·비용과 성과계획의 대응성

각 항목을 `근거 있음 / 근거 부족 / 판단 불가`로 저장하고 원문 페이지를 보존합니다.
완료율은 데이터 신뢰도에만 씁니다.

```text
evidence_completeness = 확인된 필수 근거 수 / 필수 근거 수
```

### 9.2 필요성·유사중복

필요성은 X입니다. 유사중복은 텍스트 모델로 후보를 좁힐 수 있습니다.

```text
overlap_candidate_score
= max cosine_similarity(목적 + 대상 + 수단 + 지역 + 전달체계)
```

유사도가 높아도 보완관계나 역할분담일 수 있으므로 `중복` 판정이 아니라 원문 검토
후보로만 씁니다.

### 9.3 형평성·지속가능성

수혜자·지역·소득 자료가 있으면 다음을 제시할 수 있습니다.

```text
coverage_rate = 실제 수혜자 / 적격 대상자
regional_gap = max(지역별 수혜율) - min(지역별 수혜율)
real_budget_CAGR = (real_budget_T / real_budget_0)^(1/T) - 1
own_source_ratio = 자체수입 / 총사업비
```

형평성은 단순 격차가 정책목적에 반하는지 전문가가 해석해야 합니다. 지속가능성도
예산증가 자체가 문제는 아니므로 의무부담·자체수입·종료 이후 비용과 함께 봅니다.
현재는 C입니다.

## 10. 값의 비교 방법

원 단위가 다른 변수는 최소–최대 정규화보다 동료집단 경험백분위를 우선합니다.

```text
lower_is_worse_percentile_i
= count(x_j >= x_i, j in g) / n_g

higher_is_worse_percentile_i
= count(x_j <= x_i, j in g) / n_g
```

표현상 혼란을 막기 위해 최종 저장값은 항상 `값이 클수록 점검 강함`으로 방향을
통일합니다. 동률이 많은 경우 평균순위를 사용하고 표본 수 `n_g`를 함께 표시합니다.

이상치 민감도 검토에는 robust z-score를 병행합니다.

```text
robust_z = (x - median_g) / (1.4826 * MAD_g)
```

`MAD=0`이면 z-score를 만들지 않고 백분위·절대 기준만 사용합니다.

## 11. 권장 우선순위 알고리즘

### 11.1 데이터 게이트

다음 중 하나가 핵심 변수에 있으면 정책 신호를 만들지 않고 `DATA_FIRST`로 보냅니다.

- 프로그램·세부사업 키 충돌
- 금액 단위 또는 금액유형 미확정
- 집행률 분모 미확정
- 프로그램 부분연결을 전체금액으로 오인할 위험
- 성과 원문·달성률 산식의 차단 오류

### 11.2 독립 신호 벡터

```text
S_i = (
  performance_signal,
  execution_signal,
  feedback_mismatch_signal,
  budget_structure_signal
)
```

각 값은 자기 유형 안의 강도이고 서로 합산하지 않습니다.

```text
signal_family_count = count(S_i > 유형별 검토선)
repeated_family_count = count(반복 조건을 충족한 신호 유형)
max_family_severity = max(S_i)
```

유형별 검토선은 고정 기준과 동료집단 분위수의 민감도를 확인한 뒤 확정합니다.

### 11.3 업무대기열 정렬키

전체 순위를 반드시 한 줄로 보여줘야 할 때도 가중합 대신 다음 사전식 정렬키를 씁니다.

```text
1. DATA_FIRST 여부
2. 반복 신호 또는 복수 신호 여부
3. 강한 단일 신호 여부
4. signal_family_count 내림차순
5. repeated_family_count 내림차순
6. 해당 유형의 max_family_severity 내림차순
7. evidence_status
8. 실질 예산규모 백분위 내림차순
9. 안정적인 candidate_id
```

예산규모는 위험이 아니라 영향규모이므로 동률 정리와 업무량 배분에만 씁니다.
전체 순위와 부처별 순위는 같은 규칙을 쓰되, 전체 순위의 예산 백분위는 전체 동료집단,
부처별 순위는 부처 내부 백분위를 사용합니다.

### 11.4 유형별 전문가 큐

한 개의 전체 순위와 함께 다음 네 개 큐를 반드시 제공합니다.

| 큐 | 앞에 오는 후보 |
|---|---|
| 성과 미달 | 반복 미달 → 중앙부족 → 최악부족 → 지표 사용가능률 |
| 집행 관리 | 반복 저집행 → 절대·상대 기준 동시 충족 → 연말집중 → 금액 영향 |
| 성과–예산 불일치 | 미달 반복 + 실질 증액 → T+1·T+2 방향 일치 → 증액 영향 |
| 예산구조 | 큰 재배분 거리 → 집중도 급변 → 목적 외 구성 근거 → 금액 영향 |

이렇게 하면 전문가는 “왜 위에 있나”를 한 문장으로 이해하고 원문으로 이동할 수 있습니다.

## 12. 검증 방법

최종 순위를 확정하기 전에 다음을 수행합니다.

1. 변수별 유효 표본·결측·0·음수·극단값과 부처·연도·회계유형 분포를 확인합니다.
2. 고정 기준 80%·90%와 동료집단 하위 10%·20%를 비교합니다.
3. T+1과 T+2 표본을 분리하고 방향 일치·불일치를 확인합니다.
4. 명목 예산증감과 실질 예산증감의 후보 변화를 비교합니다.
5. 재정수단·기대 시차를 넣기 전후 후보 변화를 비교합니다.
6. 신호유형 하나씩 제거해 상위 후보가 얼마나 바뀌는지 봅니다.
7. 가중합 시나리오는 Spearman 순위상관, 상위 K 중복률, 순위범위로만 보고합니다.
8. 공식 평가결과와의 중첩은 외부 타당성 참고로 쓰고 정답률이라고 부르지 않습니다.
9. 상위 후보와 반례를 원문 검토합니다.
10. 제외 행 수뿐 아니라 제외 예산 비중과 부처·회계·규모 편향을 보고합니다.

   파생변수를 만듭니다.
2. 기존 집행자료에 동료집단 ECDF와 반복률을 붙입니다.
3. GDP 디플레이터를 연결해 T+1·T+2 실질 예산증감을 만듭니다.
4. 정규화 HHI, 전년 대비 HHI 변화, 세부사업 재배분 거리를 만듭니다.
5. 원문 기반으로 `성과지표 유형·기대 시차·전달방식` 세 범주만 우선 분류합니다.
6. 유형별 큐와 전체 사전식 순서를 재산출하고 민감도를 검증합니다.
7. 법정의무성, 목적 외 지출, 융자 순재정부담은 공식 근거가 확보된 사업부터 후속
   모듈로 추가합니다.

이 순서는 현재 데이터에서 계산 가능한 값부터 보강하면서도, 나중에 LLM 모듈이
`성과지표 유형·시차·전달방식·근거문장`을 반환하면 같은 스키마에 바로 끼울 수 있게
합니다.

## 15. 채택하지 않는 방식

- 네 신호를 임의 가중합해 한 점수로 만들기
- 결측을 0점으로 대체하거나 남은 변수에 가중치를 재배분하기
- 예산규모가 크다는 이유로 위험도를 올리기
- 기금·융자·일반회계를 같은 집행률 기준으로 직접 비교하기
- 프로그램 성과를 소속 세부사업 성과로 귀속하기
- 성과 양호 + 예산 감소를 성과 미달 + 예산 증가와 대칭적인 문제로 보기
- 텍스트 유사도만으로 중복사업을 확정하기
- 짧은 관측창에서 목표 도전성과 신규·종료를 확정하기

## 16. 공식 평가결과를 학습하는 분류모델과 LLM 설명

### 16.1 역할 분리

정성 항목을 LLM이 직접 `상·중·하`로 판정하게 하지 않습니다. 권장 구조는 다음과
같습니다.

```text
정량·범주형 파생변수
→ 감독학습 분류모델
→ 예측확률·분류결과·변수별 기여도
→ LLM이 제공된 값과 원문 근거만 자연어로 설명
→ 전문가 확인
```

분류모델이 판정을 만들고 LLM은 판정을 바꾸지 않습니다. LLM 입력에는 모델 버전,
예측확률, 상위 양·음 기여변수, 원값, 동료집단 백분위, 원문 근거만 넣습니다.

### 16.2 열린재정 결과의 실제 구조

[열린재정 재정사업평가결과](https://www.openfiscaldata.go.kr/op/ko/br/UOPKOBRA03?offcCd=069)의
화면·공개 조회 응답에는 다음 필드가 있습니다.

```text
평가연도, 평가제도, 소관, 회계, 프로그램, 세부사업, 결과, 평가유형, 비고
```

2026년 4개 분석부처(`019`, `075`, `102`, `162`)의 통합재정사업평가 공개 결과를
조회한 결과는 524행입니다.

| 결과 | 공개행 수 |
|---|---:|
| 사업개선 | 282 |
| 감액 | 208 |
| 정상추진 | 23 |
| 통합 | 10 |
| 폐지 | 1 |

현재 2024년 세부사업표와 `부처코드 × 정규화 사업명 × 정규화 회계명`으로 연결하면
400행(76.3%)이 정확한 1:1 연결입니다.

| 연결된 결과 | 행 수 |
|---|---:|
| 사업개선 | 215 |
| 감액 | 171 |
| 정상추진 | 11 |
| 통합 | 3 |
| 폐지 | 0 |

나머지 124행에는 2025~2026 신규사업, 명칭·회계 변화, 미수집 사업이 섞여 있으므로
유사명 자동 연결로 학습표에 넣지 않습니다.

공개 화면에서 공통으로 확인되는 것은 최종 결과 범주입니다. 사용자가 기억한
`○·△·×`가 개별 평가문항 판단이라면 해당 상세 평가보고서를 별도로 구조화해야 합니다.
최종 결과 `감액`은 `사업 필요성 낮음`과 같은 뜻이 아니므로 두 값을 같은 정답으로
사용하지 않습니다.

### 16.3 지금 학습 가능한 타깃

#### 권장 파일럿: 감액 여부

희소한 `통합·폐지`를 제외하고 다음 이진 타깃을 먼저 검토합니다.

```text
y_cut = 1  if official_result == "감액"
y_cut = 0  if official_result in {"정상추진", "사업개선"}
```

현재 정확 연결 표본은 `감액 171 : 비감액 226`, 합계 397행입니다. 표본이 크지는
않지만 해석 가능한 기초모형의 파일럿은 가능합니다.

다음 타깃은 현재 채택하지 않습니다.

- 5분류: `폐지 0`, `통합 3`, `정상추진 11` 연결행으로 학습 불가
- 정상추진 대 조치필요: 정상추진 11행으로 극심한 불균형
- 사업 필요성 상·중·하: 필요성 문항별 전문가 정답이 없음
- 2024·2025 과거 평가결과 단순 통합: 평가제도와 결과 어휘가 서로 다름

### 16.4 사업 필요성 상·중·하 모델을 만드는 조건

사업 필요성을 별도 분류하려면 최종 평가결과가 아니라 다음과 같은 문항별 라벨이
필요합니다.

```text
evaluation_id
project_id
evaluation_year
criterion = NECESSITY
expert_label = HIGH | MEDIUM | LOW
evidence_page
expert_rationale
evaluation_system
```

공식 평가표가 `○·△·×`라면 원래 의미를 확인한 뒤에만 `HIGH·MEDIUM·LOW` 또는
`충족·부분충족·미충족`으로 매핑합니다. 제도·연도별 기호 의미가 다르면 통합하지
않고 평가제도별 모델을 만듭니다.

동일한 방식으로 다음 모델을 각각 분리할 수 있습니다.

- 사업 필요성 분류모델
- 사업계획 적정성 분류모델
- 집행 효율성 분류모델
- 성과달성·우수성 분류모델

문항별 라벨 없이 최종 결과 하나로 네 축을 동시에 학습하면 어떤 이유로 감액됐는지
식별할 수 없습니다.

### 16.5 입력변수와 누출 방지

평가 시점 전에 알 수 있었던 변수만 사용합니다.

- 성과 중앙·최악 부족, 미달비율, 반복 미달
- 집행률, 동료집단 하위꼬리, 반복 저집행, 연말집중
- T+1·T+2 실질 예산증감과 불일치 신호
- 정규화 HHI, 재배분 거리, 세부사업 예산비중
- 회계유형, 검증된 재정수단, 기대 성과시차, 사업규모
- 데이터 완전성·근거상태

다음 값은 학습에서 제외합니다.

- 공식 평가결과와 평가 이후 확정된 예산
- 사업명 원문, 프로그램명 원문, 평가자·부처 담당자
- 결과를 직접 암시하는 원문 문구
- 현재 사업을 특정하는 고유 ID

부처코드는 제도적 평가성향을 외워버릴 수 있으므로 기본모형에서 제외하고, 포함모형은
민감도 분석에만 사용합니다. 프로그램 성과는 세부사업 성과로 귀속하지 않고 상위 맥락
변수임을 명시합니다.

2026 평가에 가장 가까운 입력연도가 무엇인지 공식 평가 기준기간을 확인해야 합니다.
현재 2024년 특징으로 2026 결과를 학습하면 `사전 예측 파일럿`은 가능하지만 2025년
성과·집행을 빠뜨린 최종모형은 아닙니다.

### 16.6 첫 모형과 검증

첫 모형은 표준화 수치변수와 원-핫 범주변수를 사용한 로지스틱 회귀를 권장합니다.
개별 예측의 기여도는 `표준화 변수값 × 회귀계수`로 직접 설명할 수 있습니다. 복잡한
모형은 부처 외부 검증에서 의미 있게 개선될 때만 추가합니다.

현재 환경에는 `scikit-learn`이 설치되어 있지 않습니다. 실제 구현을 승인하면 핵심
모델 의존성으로 명시적으로 추가하며, 임시 자체 최적화 코드를 만들지 않습니다.

검증은 무작위 행 분할보다 다음을 우선합니다.

1. 부처 하나를 통째로 제외하는 leave-one-ministry-out 4회 검증
2. 같은 프로그램이 양쪽에 섞이지 않는 그룹 분할
3. 통합평가 연도가 추가되면 과거연도 학습 → 미래연도 검증
4. balanced accuracy, macro F1, 감액 PR-AUC
5. Brier score와 확률 보정도
6. `상위 K개 검토`의 precision@K, recall@K
7. 다수범주·단순 규칙 기준선과 비교

전체 정확도만 제시하지 않습니다. 부처별 성능, 회계유형별 성능, 표본 밖 분포 여부와
부트스트랩 불확실성을 함께 냅니다.

### 16.7 상·중·하 표시는 예측확률의 정책 구간

모형은 먼저 확률을 냅니다.

```text
P(감액 | 평가 이전 특징)
```

대시보드의 상·중·하는 이 확률을 보여주는 업무구간으로 만들 수 있습니다. 경계는
0.5처럼 임의로 정하지 않고, 전문가가 한 번에 검토할 수 있는 건수와 감액 사례를
놓치는 비용을 이용해 precision-recall 곡선에서 결정합니다.

```text
HIGH   = 우선 검토 용량 안에서 목표 정밀도를 만족하는 구간
MEDIUM = 추가 검토 시 감액 재현율을 유의하게 높이는 구간
LOW    = 나머지 적격 구간
```

이는 `사업 필요성 상·중·하`가 아니라 `공식 감액결과 예측 가능성 상·중·하`입니다.
사업 필요성 밴드는 문항별 필요성 라벨을 확보한 뒤 별도 모델로 생성합니다.

### 16.8 LLM 설명 계약

LLM에는 다음 구조화 값만 전달합니다.

```json
{
  "predicted_class": "CUT_REVIEW_HIGH",
  "calibrated_probability": 0.73,
  "positive_contributors": [],
  "negative_contributors": [],
  "raw_feature_values": {},
  "peer_percentiles": {},
  "source_evidence": [],
  "model_version": "...",
  "feature_cutoff_date": "..."
}
```

LLM 출력은 `예측 이유`, `반대 근거`, `추가 확인사항`만 허용합니다. 새 수치·새 사실을
만들거나 예측 등급을 바꿀 수 없습니다. 근거가 부족하면 설명에 `근거 부족`을 남기며,
최종 전문가 판단과 모델 예측을 별도 열로 보존합니다.
