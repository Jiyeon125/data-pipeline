# 원본 기획서와 현재 파이프라인 대조

## 1. 결론

현재 파이프라인은 원래 기획에서 벗어난 것이 아닙니다. 예산·집행·성과를
연결해 점검 후보를 찾는 핵심 목적, 규칙 기반 유형화, 복수 기준의 민감도
검토, 대시보드 제공 방향은 유지되어 있습니다.

다만 현재 구현은 다음 상태입니다.

- 재정 데이터 수집·정규화·품질검증·독립 신호 생성은 상당 부분 완료
- 중소벤처기업부 수기 성과자료와 회계유형별 재정자료의 동년도 결합 완료
- 중기부 통합 후보표·복수 가중치 순위·Streamlit MVP는 구현 완료
- 성과지표 유형, 자율평가 의견, 다른 부처 확장은 미완료
- LLM 문서 구조화는 기본 설계와 중기부 수기 검증 기반만 있고 자동화는
  보류

원 기획서도 하나의 정답 가중치를 확정하라고 요구하지 않습니다. 참가신청서는
균등·성과중심·집행중심·재정규모 보정 등 복수 시나리오를 비교하고,
여러 시나리오에서 반복적으로 상위에 나타나는 사업과 순위 변동이 큰 사업을
구분하도록 명시합니다. 따라서 지금 필요한 것은 단일 가중치 합의가 아니라
복수 시나리오를 같은 모집단에서 재현하는 것입니다.

## 5. 원 기획에서 변경됐지만 타당한 부분

### 성과를 세부사업에 직접 귀속하지 않음

원 기획서에는 세부사업 단위 연결이 반복해서 적혀 있습니다. 그러나 실제
성과지표는 프로그램 단위이므로 프로그램 성과를 소속 세부사업의 성과로
임의 배분하면 분석 단위가 틀립니다.

현재 구조처럼 다음 단위를 분리하는 것이 타당합니다.

- 성과: `부처 × 프로그램 × 성과지표 × 연도`
- 주 분석: `부처 × 프로그램 × 연도 × 회계유형`
- 원인 확인: `부처 × 프로그램 × 세부사업 × 연도`

세부사업은 프로그램 신호의 원인을 확인하는 드릴다운 단위로 사용합니다.

### 일반회계·특별회계·기금을 분리

원 기획의 단순 사업 단위 집계보다 현재 회계유형 분리가 정확합니다.
기금은 지출계획현액을 분모로 사용하고, 일반·특별회계와 섞지 않습니다.

### 자동 정책판정을 보수적으로 변경

초안의 `확대 검토형`, `구조조정 검토형`은 데이터만으로 정책 결론을
확정하는 것으로 오해될 수 있습니다. 현재처럼 다음 표현을 사용하는 것이
안전합니다.

- 점검 우선순위
- 추가 설명 필요
- 집행설명필요
- 성과지표 재설계 검토
- 사업구조 변경 여부 확인
- 데이터 검증 우선
- 원문 검토 필요

### LLM 자동화보다 수기 중기부 시범을 먼저 수행

토큰과 검수 여건을 고려해 수기 구조화 파일로 중기부 연결 가능성을 먼저
확인한 것은 원 기획의 Human-in-the-loop 원칙에 부합합니다. LLM은 이
검증된 구조를 반복 자동화하는 후속 단계로 두는 것이 맞습니다.

## 6. 지금 결정해야 할 기준

### 지금 확정하지 않아도 되는 것

- 하나의 최종 가중치
- 전체 사업의 단일 1위부터 N위 순위
- 정책적 확대·축소·폐지 판정

원 신청서에 따라 복수 시나리오와 순위 안정성을 제시하면 됩니다.

### 현재 적용 가능한 잠정 기준

- 집행률 80% 미만: 강한 집행설명필요 신호
- 집행률 80% 이상 90% 미만: 주의 신호
- 비교집단 하위 10%: 보조 신호
- 비교집단 하위 20%: 민감도
- 같은 신호 2회 이상이면서 유효연도의 50% 이상: 반복 후보
- 4분기 40% 이상, 12월 20% 이상: 연말집중 탐색 신호
- 데이터 조인·분모·금액 검증 문제가 있으면 정책 신호보다
  데이터 검증을 먼저 표시

### 추가 합의가 필요한 것

1. 성과지표 유형을 누가 어떤 검수표로 분류할지
2. 이월 집중 신호의 최소 금액과 비중
3. 사업규모를 위험점수로 넣을지, 영향도 정렬에만 사용할지
4. 성과·집행 괴리와 반복 신호를 어느 우선순위 단계에 둘지
5. 자율평가 자료를 본선 MVP에 포함할지 후속 확장으로 둘지

사업규모는 현재 단계에서 위험점수보다 영향도 정렬 기준으로 사용하는 것을
권장합니다. 큰 사업이라는 사실 자체는 위험이 아니기 때문입니다.

## 7. 권장 MVP

### 1단계: 중기부 통합 우선순위 후보표

한 행을 `부처 × 프로그램 × 연도 × 회계유형`으로 고정하고 다음 열을
독립적으로 유지합니다.

- 성과 미달·혼합·목표 이상 건수
- 공식 산식 비교 제한 건수
- 집행률 절대·상대 신호
- 이월·불용 집중
- 연말집중
- 반복 신호
- 예산증감과 T+1·T+2 시차
- 재정 연결·분모·대표성 제한
- 영향 예산
- 사람이 읽을 수 있는 `priority_reason`

### 2단계: 설명 가능한 우선순위 단계

- `DATA_REVIEW`: 데이터 검증 우선
- `MULTIPLE_SIGNAL_REVIEW`: 복수의 유효 신호
- `STRONG_SINGLE_SIGNAL_REVIEW`: 단일 강한 신호
- `MODERATE_OR_CONTEXT_REVIEW`: 주의·맥락 확인
- `INFORMATION`: 점검 신호 없음 또는 정보성

### 3단계: 원 신청서의 복수 시나리오 재현

- 균등
- 성과중심
- 집행중심
- 재정규모 보정
- 데이터 신뢰도 보정

각 시나리오별로 Spearman 순위상관, 상위 K 중복률, 사업별 순위 범위와
표준편차를 제시합니다. 시나리오가 바뀌어도 반복 상위에 나타나는 사업을
안정적인 점검 후보로 표시합니다.

### 4단계: 최소 대시보드

새 분석 로직을 대시보드 안에 작성하지 않습니다. 검증 완료된 통합 후보표를
읽어 다음 네 화면만 먼저 구현합니다.

1. 전체 개요와 데이터 커버리지
2. 점검 후보 목록과 필터
3. 프로그램 상세 및 세부사업 드릴다운
4. 기준·시나리오 민감도 비교

성과지표 품질, LLM 파싱 검증, 자율평가 의견, 정책제언 화면은 데이터가
준비된 뒤 추가합니다.

## 8. 권장 작업 순서

1. 중기부 통합 우선순위 후보표 구현
2. 중기부 성과지표 63개 유형 수기 분류
3. 규칙 기반 단계와 `priority_reason` 검증
4. 복수 가중치 시나리오와 순위 안정성 검증
5. 최소 대시보드 구현
6. 최종 보고서·사례카드 작성
7. 이후 LLM 문서 구조화와 다른 부처 확장

이 순서는 원 신청서의 핵심 약속을 지키면서도, 아직 검증되지 않은 LLM과
화면 기능 때문에 현재 분석이 다시 흔들리는 것을 방지합니다.

권장 MVP의 1~3단계를 중기부 표본에 구현했습니다.

- 후보표: 66행 중 공동분석 58행, 점검 후보 45행
- 시나리오 순위 적격: 38행
- 별도 데이터 검증 큐: 8행

5개의 독립 사업으로 해석하지 않습니다. 6~10위 경계는 가중치에 따라 바뀌어
단일 순위 확정에 부적합합니다. 성과지표 유형과 자율평가 의견은 아직 없어
