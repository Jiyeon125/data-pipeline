# 3개 부처 성과지표 PDF 원문 검수 안내

## 먼저 결론

361행을 전부 검수하지 않습니다.

- 필수 검수: 201행
  - 값 불일치 19행
  - 같은 지표명으로 프로그램이 모호한 행 6행
  - 수기값은 있으나 PDF 근거를 자동으로 찾지 못한 행 2행
  - OCR 또는 페이지 육안 판독이 필요한 행 174행
- 자동 강근거: 160행
  - 원문 자동 대조 일치 54행
  - 별첨6의 목표 변경 전·후가 보고서와 이어지는 행 106행

자동 강근거 160행은 발표 사례로 선택되었을 때만 표본 검수합니다. 기본 작업은
필수 201행이며, 우선순위 정책의 권장 검토군을 적용하면 그중 30행부터 확인하면
됩니다.

권장 정책 초안의 30행 목록은 다음 파일에 있습니다.

```text
data/analytics/priority_policy_decision_support/recommended_source_review_queue.csv
```

8. PDF·수기 엑셀·자동 대조 결과 파일은 직접 수정하지 마세요.

## 어떤 화면을 사용하나요

저장소 루트에서 다음 명령을 실행합니다.

```powershell
.\.venv\Scripts\python.exe -m streamlit run src\fiscal_dashboard\app.py
```

대시보드에서 `5. 원문 검수`를 선택합니다. 기본 화면은 필수 검수 201행만
보여줍니다. `자동 강근거 160행도 표본 검수 대상으로 보기`를 켜야 나머지
160행이 추가됩니다.

엑셀을 직접 수정하는 방식보다 대시보드를 사용합니다. 대시보드는 수기 입력,
PDF 자동 추출값, 근거 페이지 이미지를 한 화면에 보여주고 검수 기록을
`source_indicator_id` 기준으로 안전하게 덮어씁니다.

부처코드는 고용노동부 `019`, 보건복지부 `075`, 과학기술정보통신부 `162`입니다.
앞자리 0을 지우지 않습니다.

## 검수 순서

### 1순위: 불일치·모호·PDF 근거 누락 27행

1. `VALUE_MISMATCH` 19행
   - 수기값과 PDF값이 다릅니다.
   - 계획서 목표, 보고서 목표·실적·공식 달성률, 별첨6 변경표를 모두 확인합니다.
2. `AMBIGUOUS` 6행
   - 같은 연도에 같은 지표명이 여러 프로그램에 있습니다.
   - 지표명만 보지 말고 프로그램명과 표 위치가 같은지 확인합니다.
3. `PDF_MISSING_MANUAL_PRESENT` 2행
   - 수기값은 있지만 자동으로 원문 위치를 찾지 못했습니다.
   - 원문에서 직접 찾고, 끝까지 근거가 없으면 `현재 문서로 확인 불가`로 남깁니다.

### 2순위: OCR 필요 174행

`OCR_REQUIRED`는 자동 추출값을 믿지 않습니다. 화면에 렌더링된 페이지에서
인쇄된 숫자를 직접 읽습니다.

페이지가 `?쪽`으로 표시되면 값이 없다는 뜻이 아니라 자동 위치 특정에
실패했다는 뜻입니다. 안내된 파일을 직접 열고 다음 순서로 찾습니다.

1. 프로그램명
2. 지표명
3. 계획 목표
4. 별첨6의 목표 변경 전·후 및 변경 사유
5. 보고서 목표·실적·공식 달성률

### 3순위: 자동 강근거 160행

`EXACT_MATCH`와 `MATCH_AFTER_CHANGE`는 전체 검수 대상이 아닙니다. 다음 경우만
사람이 확인합니다.

- 발표 사례로 사용할 프로그램
- 최종 우선 검토군에 포함된 프로그램
- 동일 지표명이 반복되는 프로그램
- 자동 변경표와 보고서 본표가 충돌한 흔적이 있는 경우

## 행 하나에서 무엇을 확인하나요

다음 다섯 값을 확인합니다.

1. 지표명과 프로그램 소속
2. 성과계획서의 최초 목표
3. 성과보고서의 최종 목표
4. 성과보고서의 실적
5. 성과보고서의 공식 달성률

별첨6 변경표는 목표 변경의 근거입니다. 실적과 공식 달성률은 성과보고서의
성과표를 우선합니다. 변경표와 성과표가 충돌하면 임의로 선택하지 않습니다.

## 검수 결과 선택 기준

| 선택값 | 사용 조건 | 분석 처리 |
|---|---|---|
| `원문과 일치` | 프로그램·지표·목표·실적·달성률이 원문과 수기값에 일치 | 근거 확인 완료 |
| `수정 필요` | 원문에서 정확한 값이 확인됐지만 수기값 또는 자동값이 틀림 | 메모에 정답을 기록하되 자동 반영 전까지 확정 순위에 사용하지 않음 |
| `현재 문서로 확인 불가` | 계획서·보고서·변경표를 확인해도 값이나 소속을 확정할 수 없음 | 원문 의존 분석에서 제외 |
| `보류` | 시간이 부족하거나 추가 파일이 필요함 | 미완료로 유지 |

`수정 필요`는 원본이나 분석값을 자동으로 고치지 않습니다. 수정 오버레이
파이프라인이 반영되기 전까지는 데이터 검토 상태입니다.

## 검수 메모 작성 형식

다음 형식을 그대로 복사해 사용합니다.

```text
[파일·쪽] 파일명 / 분리 PDF 00쪽 / 원본 000쪽
[확인값] 지표명= / 계획목표= / 보고목표= / 실적= / 공식달성률=
[판정근거] 프로그램명과 표 위치 일치 / 별첨6 변경 전·후 확인 / OCR 오독 등
[후속조치] 없음 / 수정 오버레이 필요 / 추가 원문 필요
```

`원문과 일치`라도 확인한 파일과 쪽을 적습니다. `수정 필요`는 정확한 값과
단위를 빠뜨리면 완료로 인정하지 않습니다.

## 검수 완료 조건

- 검수자 이름과 메모가 비어 있지 않음
- 확인한 파일과 페이지가 기록됨
- `수정 필요`에는 정답 값과 단위가 기록됨
- `현재 문서로 확인 불가`에는 찾아본 파일 범위가 기록됨
- 같은 `source_indicator_id`가 중복되지 않음
- 우선 검토군에 필요한 지표가 모두 `원문과 일치`, `수정 필요`,
  `현재 문서로 확인 불가` 중 하나로 정리됨

## 하지 말아야 할 것

- PDF, 수기 엑셀, 자동 대조 Parquet을 직접 덮어쓰지 않습니다.
- OCR 숫자를 원문 확인 없이 정답으로 채택하지 않습니다.
- 달성률을 재계산했다는 이유로 공식 달성률을 덮어쓰지 않습니다.
- 값이 안 보인다는 이유로 0을 입력하지 않습니다.
- `수정 필요`를 선택했는데 정답을 메모에 쓰지 않는 상태로 끝내지 않습니다.
