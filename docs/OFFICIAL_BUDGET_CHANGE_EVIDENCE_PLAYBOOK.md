# 예산 증감 사유 공식근거 탐색·검수 경로

## 1. 결론

예산 증감의 **금액과 주요 세부사업**은 재정 API와 국회예산정책처 자료로
대조할 수 있습니다. 다만 “왜 증액·감액했는가”는 공식 문서에 직접 적힌 경우에만
확정합니다. 집행부진 사유나 사업 단계는 유력한 맥락이지만 다음 연도 예산 증감의
원인으로 자동 연결하지 않습니다.

가장 먼저 프로그램 전체금액과 분석대상 소계를 분리해야 합니다.

|사례|2023 프로그램 전체|2024 프로그램 전체|전체 증감|연속 분석사업 소계 증감|판단|
|---|---:|---:|---:|---:|---|
|국립춘천병원|158.31억원|171.88억원|+8.6%|+20.5%|방향 일치|
|국립나주병원|220.11억원|241.45억원|+9.7%|-3.6%|방향 불일치|

국립나주병원의 `-3.6%`는 인건비·기본경비 등을 제외한 연속 분석사업 소계입니다.
따라서 이를 프로그램 전체 감액으로 표현하지 않습니다. 프로그램 예산 반응은
전체금액으로, 변화 원인 드릴다운은 세부사업 소계로 봅니다.

## 2. 이번 탐색 결과

### 2.1 국립춘천병원

- 국회예산정책처의
  [2024년도 예산안 위원회별 분석](https://www.nabo.go.kr/board/file/down.do?fid=33317752)
  29쪽은 `춘천병원 병원관리 및 운영(자본)`이 12.38억원에서 24.73억원으로
  12.35억원 증가했고, `교육 및 실습 수입대체경비`가 0.22억원에서 1억원으로
  0.78억원 증가했다고 제시합니다.
- 같은 두 금액은 로컬 재정 API 자료와 일치합니다. 프로그램 전체 순증
  13.57억원 가운데 자본사업 증가가 가장 큰 변화입니다.
- 국회예산정책처의
  [2023회계연도 결산 총괄 분석 II](https://www.nabo.go.kr/board/file/down.do?fid=33318070)
  113쪽은 해당 자본사업의 2023년 집행률을 31.3%, 최근 4년 평균을 61.6%로
  제시하고, 집행부진 사유를 `설계용역 계약지연에 따른 공사 계약기간 미도래`로
  기록합니다.
- 확인 가능한 해석은 “자본사업이 증액의 주된 금액 요인이며, 같은 사업의
  2023년 공정은 설계·계약 단계에서 지연됐다”까지입니다. 지연 때문에 2024년
  예산이 늘었다고 단정할 직접 문장은 아직 찾지 못했습니다.

### 2.2 국립나주병원

- 전체 프로그램 예산은 220.11억원에서 241.45억원으로 증가했습니다.
  국회예산정책처의
  [2024년도 재정총량 분석 I](https://www.nabo.go.kr/board/file/down.do?fid=33317780)
  도 국립나주병원 특별회계를 2023년 220억원, 2024년 예산안 241억원,
  증가율 9.7%로 제시합니다.
- 연속 분석사업 소계는 73.06억원에서 70.44억원으로 줄었습니다. 주요 감소는
  `병원관리 및 운영(손익)` -2.07억원과 `병원관리 및 운영(자본)` -0.98억원입니다.
  그러나 인건비가 127.98억원에서 150.84억원으로 증가해 전체 방향은 증가입니다.
- [2023회계연도 결산 총괄 분석 II](https://www.nabo.go.kr/board/file/down.do?fid=33318070)
  113쪽은 `교육 및 실습 수입대체경비`의 2023년 집행률을 53.5%로 제시하고,
  집행부진 사유를 `사업신청 저조, 사업대상자 감소 등`으로 기록합니다.
- 이 집행부진 사유는 해당 교육사업의 맥락입니다. 프로그램 전체 증액이나
  병원관리 사업 감액의 직접 사유로 확대 해석하지 않습니다.

## 3. 반복 가능한 탐색 순서

### 0단계. 금액 범위부터 대조

다음 세 금액을 별도 열로 만듭니다.

```text
program_total_original_budget
program_analysis_original_budget
feedback_base_budget_t1
```

프로그램 전체와 연속 분석사업 소계의 증감 방향이 다르면 탐색을 중단하지는 않되,
대시보드의 주된 방향은 프로그램 전체로 표시하고 소계는 드릴다운으로 내립니다.

### 1단계. 검색키 생성

최소 검색키는 다음과 같습니다.

```text
부처명
기준연도와 다음 연도
회계명
프로그램 코드·명
증감 기여 상위 세부사업 코드·명
기준연도 금액과 다음 연도 금액
```

명칭만 검색하지 않고 금액, 회계명, 연도를 함께 사용합니다.

### 2단계. 공식 문서 탐색 순서

1. 부처의 해당 연도 `예산 및 기금운용계획 사업설명자료`
2. 국회예산정책처 `다음 연도 예산안 위원회별 분석`
3. 국회예산정책처 `기준연도 결산 분석`
4. 국회 상임위·예결위 검토보고서
5. 소속기관의 계약·입찰·업무계획·정보공개 자료
6. 직접 사유가 없으면 정보공개청구 또는 담당부서 확인 대상으로 남김

보건복지부 자료는
[사전정보공표 게시판](https://www.mohw.go.kr/board.es?act=view&bid=0037&list_depth=1&list_no=369977&mid=a10107010000)
처럼 일반회계와 특별회계·기금 PDF가 분리될 수 있으므로 회계에 맞는 첨부를
선택합니다.

### 3단계. 증거 등급

```text
A_DIRECT
동일 연도·동일 회계·동일 세부사업 코드 또는 명칭의 금액/사유 직접 문장

B_STAGE_CONTEXT
동일 사업의 집행부진·계약·공정 단계 직접 문장이나 예산 결정 사유는 아님

C_PROGRAM_CONTEXT
동일 프로그램의 일반 정책 설명으로 특정 증감 사유는 아님

NOT_FOUND
공식 문서에서 직접 근거를 찾지 못함
```

`B_STAGE_CONTEXT`와 `C_PROGRAM_CONTEXT`는 원인으로 서술하지 않습니다.

## 4. 향후 LLM 입력·출력 계약

LLM은 검색 후보 생성과 문장 추출까지만 맡깁니다. 최종 증거 등급과 해석은 사람이
승인합니다.

```json
{
  "case_key": {
    "ministry_code": "075",
    "base_year": 2023,
    "outcome_year": 2024,
    "account_type": "RESPONSIBLE_OPERATION_ACCOUNT",
    "program_code": "4000",
    "program_name": "국립춘천병원",
    "subactivity_code": "301",
    "subactivity_name": "춘천병원 병원관리 및 운영(자본)"
  },
  "claim": {
    "claim_type": "BUDGET_CHANGE_REASON",
    "base_amount": 1238000000,
    "outcome_amount": 2473000000,
    "unit": "KRW"
  },
  "evidence": {
    "document_title": null,
    "official_url": null,
    "page": null,
    "evidence_text": null,
    "evidence_grade": "NOT_FOUND",
    "supports_claim": false
  },
  "validation": {
    "year_match": false,
    "account_match": false,
    "program_match": false,
    "project_match": false,
    "amount_match": false,
    "human_review_status": "PENDING"
  }
}
```

LLM 지시문에는 다음 제한을 고정합니다.

```text
문서에 존재하는 값과 문장만 반환한다.
예산 증감 사유가 직접 쓰이지 않았으면 evidence_text=null로 반환한다.
집행부진 사유를 다음 연도 예산 증감 원인으로 바꾸어 쓰지 않는다.
페이지, 문서명, 공식 URL, 표의 금액 단위를 반드시 보존한다.
명칭·연도·회계·금액 중 하나라도 충돌하면 supports_claim=false로 반환한다.
```

## 5. 사람 검수 체크리스트

1. 프로그램 전체와 분석 소계가 구분되어 있는가
2. 기준연도·예산연도·회계가 일치하는가
3. 원과 백만원·억원 단위가 일치하는가
4. 세부사업 코드 또는 명칭이 동일한가
5. 금액이 API와 공식 표에서 일치하는가
6. 인용문이 “금액”, “사업 단계”, “증감 사유” 중 무엇을 직접 증명하는가
7. LLM이 집행부진 사유를 증감 결정 사유로 추론하지 않았는가
8. 미확인은 `NOT_FOUND`로 남아 있는가

사람이 승인한 행만 발표 근거와 대시보드 설명문에 사용합니다.
