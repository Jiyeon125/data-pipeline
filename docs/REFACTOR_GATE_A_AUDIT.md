# 전면 구조개선 Gate A 기준선 감사

## 결론

Gate A의 목적은 현재 파이프라인을 곧바로 재작성하는 것이 아니라, 무엇을 보존하고
무엇을 고쳐야 하는지 실데이터로 고정하는 것입니다. 4개 부처(019·075·102·162),
2022~2024년 범위에서 저장소·데이터·실행 경로와 핵심 수치를 재현했습니다.

현재 파이프라인은 재생성 가능한 Parquet 계층과 CLI가 이미 있어 전면 재작성보다
`확장 → 병행 검증 → 전환` 방식이 안전합니다. 다만 최종 우선순위 산출 전에
시간축 누출, 식별자 충돌, UNKNOWN 비교집단, 성과 연결 금액 중복을 먼저 고쳐야
합니다.

## 재현 기준

- 저장소 루트: `data-pipeline`
- Git 기준점: `3767dcdd7701e5dd1b13072964da6e33df762471`

  과학기술정보통신부 162

- 원본 변경: 없음

## 현재 실행·데이터 흐름

```text
공식 API·PDF·결산 원본 (data/raw)
  + 사람 확정값 (data/manual)
  + 범위·규칙 (configs)
        ↓
수집·문서처리 중간물 (data/interim)
        ↓
예산·월별집행·결산·성과 정규화 (data/processed/*)
        ↓
사업-연도·프로그램-연도 마스터 (data/processed/masters)
        ↓
재정신호·후보·민감도 (data/analytics)
        ↓
승인된 소비계약 (data/exports) + 보고서·그림 (artifacts)
        ↓
Streamlit 점검 대시보드
```

실행 진입점은 `openfiscal`, `fiscal-master`, `fiscal-analytics`,
`fiscal-performance` 네 CLI입니다. 대시보드는
`data/analytics/multi_ministry_priority_scenarios`의 후보·신호 산출물을 읽습니다.

## 원천과 생성물의 경계

| 구분 | 경로 | 취급 |
|---|---|---|
| 공식 원천 | `data/raw` | 읽기 전용, 재생성 불가 |
| 사람 결정 | `data/manual` | 승인 이력 보존, 자동 덮어쓰기 금지 |
| 규칙 원천 | `configs` | 버전 관리 대상 |
| 중간 처리 | `data/interim` | 재생성 가능, 11,252파일·약 2.02GB |
| 정규화·마스터 | `data/processed` | 코드로 재생성 가능 |
| 분석 결과 | `data/analytics` | 코드로 재생성 가능 |
| 소비자 계약 | `data/exports` | 승인된 스키마만 제공 |
| 보고 산출물 | `artifacts` | 재생성 가능 |

전체 조사 범위는 12,051파일·약 2.72GB입니다. 병목은 코드가 아니라
`data/interim`의 파일 수와 용량입니다. Gate A에서는 파일 이동이나 삭제를 하지
않았습니다.

## grain·식별자·조인 감사

1. `project_year_financial_v2.project_id`는 연도를 포함하므로 안정적인 사업 ID가
   아니라 사업-연도 관측 ID입니다.
2. 분류 테이블의 코드 없는 10행은 이름도 비어 있어 하나의 해시 ID로 충돌합니다.
   출처 행 기반 임시 ID와 `identity_status`가 필요합니다.
3. 프로그램-연도 실제 생산 grain에는 `program_name`이 포함되지만
   `configs/join_keys.yaml` 선언에는 빠져 있습니다. 설정과 생산자의 계약을
   일치시켜야 합니다.
4. 월별 집행의 선언 키에는 1,224개 중복 행이 있습니다. 원천 중복·복수 행 구성을
   구분하기 전 임의 제거할 수 없습니다.
5. 금액 이벤트는 여러 `amount_type`을 가지므로 모든 금액 열을 한 번에 합산하면
   안 됩니다.
6. 프로그램 성과를 세부사업 성과로 귀속하지 않습니다. 프로그램 성과는 상위 맥락,
   세부사업은 재정 신호 원인을 보는 드릴다운으로 유지합니다.

## 시간·회계·재원 구조 감사

- 2022~2024년 분석후보에 2025년 결과 금액이 노출된 신호가 T+1 16건,
  T+2 19건이며 프로그램 전체금액 기준 후보-시차 노출은 70행입니다.
  기준연도와 후속 결과연도를 물리적으로 분리해야 합니다.
- 예산 환류 분석 부적격 465행·기준 본예산 92,114,396,000,000원이 현재 체인에
  섞일 수 있습니다. 동년도 점검 적격성과 T+1/T+2 환류 적격성을 분리해야 합니다.
- 특별회계 grain 불일치로 후보 4행이 `UNMATCHED`입니다. 회계 세부구분을 보존한 뒤
  공식 단위로 집계해야 합니다.
- 기금 집행률 분모가 0인 사업-연도는 현재 27행입니다. 이 행은 전체 분석에서
  삭제하지 않고 집행률 신호만 제한해야 합니다.
- 현재 `fiscal_instrument`에는 지원방식 134행과 사업특성 2,757행이 같은 축에
  섞여 있습니다. 지원방식과 사업특성은 별도 assertion으로 분리해야 합니다.

## Gate A 판정과 다음 단계

Gate A는 다음 조건을 충족했습니다.

- 저장소·데이터·실행 경로를 실제 파일과 CLI로 재현했습니다.
- 기준 수치와 체크섬을 자동 산출합니다.
- 원천·수기확정·재생성·소비계약을 분리했습니다.
- grain·ID·시간축·회계·재원·조인 위험을 실제 행과 금액으로 특정했습니다.
- 원본 삭제, 대규모 이동, 핵심 파이프라인 재작성은 하지 않았습니다.

다음 Gate B에서는 현재 실행시간·메모리·파일 수를 측정하고 최소 3개 물리 구조
대안을 비교합니다. 저장방식과 영속 식별자 선택은 결과와 마이그레이션 범위를
바꾸므로, 비교 근거를 만든 뒤 미니 PT로 한 번에 결정받습니다.
