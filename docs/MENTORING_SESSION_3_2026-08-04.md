## 0. 한 줄 결론

통합 가중합 1등보다 **유형별 점검 사유·대기열**이 본편이다.  
성과미달만으로 최우선이 되지 않고, 예산규모는 단독 서열이 아니며,  
환류 확인은 **T+2 주 / T+1 보조**다.  
고정 Top5·10은 최종 기준이 아니라 발표·업무량용이다.

## 1. 재정·정책 질문과 답

### Q1. 성과미달만으로 예산 점검 후보?

| | |
|---|---|
| 질문 요지 | 성과미달만으로 후보 포함? 추가 재정 신호가 있어야 하나? |
| 멘토 답 | 후보는 가능. **최우선으로 바로 올리면 안 됨.** 최우선에는 심각성·반복성·재정규모·집행이행·후속 예산변화 중 **하나 이상** 추가 근거. |
| 프로젝트 반영 | `review_intensity`: 성과미달만으로 `STRONG_SINGLE` 올리지 않음. 집행 강신호·성과미달+후속예산증가 등이 있을 때만 강한 단일. 본편은 유형 레인 + `signal_score`(규모 제외). |

### Q2. 융자·기금의 재정영향도 측정

| | |
|---|---|
| 질문 요지 | 총운용·출연·순부담·융자공급·지출액 중 무엇? 일반회계와 동일 규모지표? |
| 멘토 답 | **단일 금액 통일 비교 금지.** 실제 공급·지원 규모를 **별도 축.** 총운용은 구조 설명용. 일반회계와 원금액 직접 서열 비교 지양 → 재정수단별 상대 위치. |
| 프로젝트 반영 | **미완(후속).** 대시보드 기금 경고 유지. 본예산 백분위로 기금·융자를 같은 줄에 세우지 않도록 `fiscal_impact`를 본편 점수에서 제외한 상태. 공급·회수·순부담 원자료 확보 후 별도 축 설계. |

### Q3. 통합순위 vs 유형별 후보군

| | |
|---|---|
| 질문 요지 | 성과·집행·불일치·구조를 한 순위로? 유형별이 나은가? |
| 멘토 답 | **유형별 먼저**, 유형 안 우선순위. 통합순위는 탐색 **보조**. 복합지표는 맥락을 가리고 가중치에 민감. |
| 프로젝트 반영 | **반영.** 균등·성과·집행·재정영향 시나리오 **본편 UI 제거.** 업무대기열 = 신호 유형 레인. |

### Q4. 성과↓예산↑ vs 성과↑예산↓ 비대칭

| | |
|---|---|
| 멘토 답 | **타당.** 전자=재원배분·계획 확인 신호, 후자=종료·효율화·이관 등 **구조변경 확인** 신호. |
| 프로젝트 반영 | **이미 반영.** `LOW_PERFORMANCE_BUDGET_INCREASE_*` vs `GOOD_PERFORMANCE_BUDGET_DECREASE_*_CONTEXT` 분리. |

### Q5. 환류 시차 T+1 vs T+2

| | |
|---|---|
| 멘토 답 | 성과보고서 환류의 **주 분석 = T+2**. T+1은 조기조정·동시정책 **보조**. 동년도는 환류가 아니라 **구조적 정합성**. |
| 프로젝트 반영 | 문서·대시보드 문구에 T+2 주 / T+1 보조 명시. 필드·코호트는 계속 분리 유지. (`MENTORING_GUIDE` 과거 “둘 다 보고 선택”을 이번 세션으로 갱신) |

### Q6. 후보 제시 최소 근거 5가지

1. 분석 대상·시계열 **동일성**  
2. 성과자료 **신뢰성**  
3. 예산·집행 **비교가능성**  
4. 사업 **회계구조 변화** 여부  
5. 신호를 설명·반박할 **공식 근거**  

미확인이 크면 우선후보가 아니라 **추가 확인 후보**로 하향.  
**프로젝트 반영:** 체크리스트를 대시보드·본 문서에 게시. 자동 게이트 코드화는 후속.

### Q7. 인과관계 오해 방지

발표에 **분석 가능/불가능**, **성과·예산 시간축**을 명시.  
**프로젝트 반영:** 대시보드·발표 문구 유지·강화. 실패·낭비·삭감 자동 판정 금지 유지.

## 2. 데이터분석 질문과 답

> **데분 Q4**(원문검수 신뢰도를 적격/시나리오/경고 중 어디에),  
> **데분 Q6**(라벨 없는 타당성 검증 최소 조합)은 **시간상 미진행**.

### 데분 Q1. 행 단위 vs 프로그램 단위

| | |
|---|---|
| 멘토 답 | 최종 후보·안정성 = **고유 프로그램**. 행 = 원인 진단용. |
| 프로젝트 반영 | 현재 대기열 grain은 프로그램×연도×회계유형(행). 발표·의사결정은 프로그램 단위로 묶는 요약 유지. 세부사업은 드릴다운. |
| 주의 | `MENTORING_GUIDE` 31.12의 “최종 후보는 세부사업 우선”과 **충돌**. **3차 세션·사전질문 답변을 우선**하고, 세부사업은 원인 확인 단위로 둔다. |

### 데분 Q2. 성과미달을 복합점수 대신 진입조건

| | |
|---|---|
| 멘토 답 | **타당.** 진입 후 미달 정도·지표 수·반복·체감으로 차등. 포화·예산 독점 완화. |
| 프로젝트 반영 | 부분 반영. 본편에서 규모 축 제거. 성과미달만으로 강한 단일 금지. `signal_score`에 성과 강도는 유지하되, 진입·레인과 역할을 분리해 설명. 완전 “진입만” 구조는 후속 정교화. |

### 데분 Q3. 시나리오 상관이 높아도 규모 지배일 수 있음

| | |
|---|---|
| 사전질문 | 변수 제거·규모 제외·프로그램 단위 TopK 중 무엇을 우선하나? |
| 판단 | 본편에서 가중 시나리오 자체를 제거. 규모 제외(`signal_score`)·유형 대기열·프로그램 단위가 우선 검증. |
| 프로젝트 반영 | **반영** (시나리오 UI 제거 + 규모 동률 분리). |

### 데분 Q5. 고정 Top5·10

| | |
|---|---|
| 멘토 답 | 최종보고서 기준으로는 **부적절**. 조건 충족 프로그램을 **등급**으로. TopK는 발표 사례·업무량용. 누적 예산비중은 포괄범위 보조지표. |
| 프로젝트 반영 | 문서·대시보드에 “고정 TopK ≠ 최종 기준” 명시. 등급제 UI는 후속. |

### 데분 Q4·Q6 (미진행)

- Q4: 검수 미완료를 순위 적격 제한 vs 신뢰도 시나리오 vs 경고만 → **추후**

## 4. 발표용 문장

> 본편은 성과·집행·예산구조 등 **점검 사유별 대기열**이다.  
> 예산 규모는 위험 점수가 아니라 동률·파급 설명에만 쓴다.  
> 성과미달만으로 최우선 후보로 올리지 않으며, 환류는 T+2를 주로 본다.  
> 고정 상위 5·10개는 발표·업무량용이지 최종 판정 기준이 아니다.  
> 실패·낭비·삭감 자동 판정이 아니다.
