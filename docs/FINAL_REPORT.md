# 4개 부처 재정사업 점검 우선순위 분석 보고서

기준선: `manual-v1` · 분석일: 2026-07-31

## 결론

현재 결과는 고용노동부·보건복지부·중소벤처기업부·과학기술정보통신부의
2022~2024년 수기 구조화 성과자료와 재정자료를 연결해, 실무자가 먼저 설명을
요청할 프로그램과 세부사업을 좁히는 데 사용할 수 있습니다.

자동 삭감·증액·실패 판정은 만들지 않았습니다. 기본 업무순서는 가중합 점수가
아니라 데이터 검증 → 반복·복수 신호 → 강한 단일 신호 → 단일 신호 → 맥락
검토 → 신호 미검출 순입니다. 네 가지 가중 시나리오는 결과가 가중치에 얼마나
민감한지 확인하는 고급 분석으로만 남겼습니다.

## 분석 범위와 단위

- 대상 부처: `019`, `075`, `102`, `162`
- 기간: 2022~2024년
- 성과 단위: 부처 × 프로그램 × 성과지표 × 회계연도
- 주 점검 단위: 부처 × 프로그램 × 회계연도 × 회계유형
- 원인 확인 단위: 부처 × 프로그램 × 세부사업 × 회계연도 × 회계유형
- 성과지표 424행: 고용 62, 복지 116, 중기 63, 과기 183
- 점검 후보 412행: 고용 54, 복지 116, 중기 65, 과기 177

프로그램 성과를 세부사업 성과로 귀속하지 않습니다. 프로그램에서 신호를 찾은
뒤 세부사업은 예산·집행·구조 변화의 원인을 확인하는 드릴다운으로만 사용합니다.

정의한 점검 신호가 잡히지 않았다는 뜻입니다.

## 후속 예산 변화

성과와 후속 예산을 비교할 때 프로그램 전체 본예산과 연속 관측 세부사업 소계를
분리했습니다.

- 주 신호: 단일 회계유형 프로그램의 `program_total_original_budget`
- 보조 대조: 같은 세부사업만 이어 붙인 연속 관측 소계
- T+1과 T+2는 별도 코호트로 유지
- 혼합 회계 프로그램은 전체예산 환류 비교에서 제한
- 후보 회계와 프로그램 회계가 다른 3행(T+1), 1행(T+2)은 데이터 확인 상태

프로그램 전체예산 비교 가능 행은 T+1 107행, T+2 69행입니다. 연속 세부사업
소계의 완전 연결은 T+1 108행, T+2 42행입니다. 두 금액의 T+1 증감 방향이
다른 행은 4행이며, 이 경우 프로그램 전체 방향을 우선하고 세부사업 구성 변화를
확인합니다.

성과 미달과 프로그램 전체 T+1 예산을 함께 확인할 수 있는 행은 29행입니다.
22행은 증가, 7행은 감소했습니다. 원문 근거상태가 `CONFIRMED`인 6행도 증가
5행, 감소 1행으로 갈렸습니다. 따라서 성과 미달은 자동 감액·증액 규칙이 아니라
예산 변화 사유를 먼저 확인할 신호입니다.

## 가중치 민감도

순위 시나리오 필수 변수가 완전한 행은 235행입니다. 균등가중·성과중심·
집행중심·재정영향 보정의 전체 Spearman 순위상관은 0.642~0.917입니다.
네 시나리오 공통 Top 5와 Top 10은 모두 0행이고, 후보별 전체 순위 범위
중앙값은 55위, 최댓값은 151위입니다.

가중치에 따라 상위 후보가 바뀌므로 단일 종합점수나 최종 1위를 제시하지
않습니다. 실무 화면은 설명 가능한 신호 유형을 먼저 보여주고, 시나리오 결과는
가중치 의존성을 확인할 때만 사용합니다.

## 원문과 데이터 품질

- 성과지표 기본키 중복: 0행
- 후보 `candidate_id` 중복: 0행
- 프로그램 성과의 세부사업 귀속: 0행
- 선정 사례의 세부사업 본예산 합계 불일치: 0행
- 프로그램 전체 본예산 집계 차이: 0원
- 중기부 수기 결측 19행: PDF 확인값으로 별도 보완, 원본 수기값은 보존
- 다른 3개 부처 공통 PDF 사람 검수 큐: 201행

낮은 집행률·연말 집중·예산 증감은 낭비나 실패가 아니라 추가 설명 필요
신호입니다. 기금은 일반·특별회계와 집행률 구조가 달라 직접 서열화하지
않습니다.

## 대시보드 사용 순서

1. 업무 현황에서 412행의 구분과 데이터 검증 대상을 확인합니다.
2. 점검대기열에서 부처·연도·회계유형을 좁힙니다.
3. 사업 상세에서 프로그램 성과와 프로그램 전체 T+1·T+2를 확인합니다.
4. 연속 세부사업 소계와 방향이 다르면 세부사업 구성 변화를 확인합니다.
5. 고급 민감도에서 전체 순위와 부처 내부 순위의 변동 범위를 확인합니다.
6. 원문 검수에서 수기값·PDF 근거·사람 판정을 함께 기록합니다.

```powershell
.venv\Scripts\python.exe -m streamlit run src/fiscal_dashboard/app.py
```

  검증했습니다.

## 다음 단계

`manual-v1` 기준선은 별도 패키지와 SHA-256으로 동결합니다. LLM 모듈은 이
기준선을 덮어쓰지 않고, 로컬 PDF 추출로 확정하지 못한 짧은 후보 구간만
구조화합니다. JSON 스키마·원문 페이지·근거문장·비용 상한·사람 검수를 모두
통과한 결과만 별도 승격하며, 실패하면 현재 수기 기준선을 그대로 사용합니다.
