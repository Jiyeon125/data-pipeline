# 중소벤처기업부 성과지표 PDF 대조 (2022~2024, 63행)

## Executive Summary

- 기존 수기 구조화 63행(부처×프로그램×성과지표×회계연도)을 중소벤처기업부
  2022~2024년 성과계획서·성과보고서 별첨 PDF 원문과 행 단위로 대조했습니다.
- **63행 중 14행만 원문으로 즉시 그대로 사용 가능(`EXACT_MATCH`)합니다.**
  나머지 49행(78%)은 전부 사람이 원문을 직접 확인해
  `review_status=CONFIRMED`로 확정했습니다(9절). 확정 후 최종
  라벨은 계획서-보고서 목표치 변경 확인(7행,
  `MATCH_AFTER_CHANGE`), 목표 변경은 해소됐으나 실적·달성률이
  수기 결측(15행, `MANUAL_MISSING_PDF_PRESENT`), OCR/사람 검토
  필요(24행, `OCR_REQUIRED`), 지표명 중복 충돌(2행, `AMBIGUOUS`),
  PDF 미기재(1행, `PDF_MISSING_MANUAL_PRESENT`)로 나뉩니다.
  (2026-07-28 보완9: 종전에 `VALUE_MISMATCH` 19행으로 표시됐던
  행은 별첨6 "성과계획서 변경 사항"표의 변경전·변경후 숫자가 이
  불일치와 정확히 일치함을 확인한 뒤 `MATCH_AFTER_CHANGE`/
  `MANUAL_MISSING_PDF_PRESENT`로 재분류했습니다. `WORK_LOG.md`
  보완9 참고.)
- 2022년 24행은 **전부** 이미지 표라 OCR 대상이었습니다. 2022년
  성과계획서 별첨1 표는 셀이 이미지로 렌더링되어 텍스트 레이어가
  없고, 로컬 OCR로 값을 찾아도 화면 판독 오류 위험이 있어 자동
  확정하지 않았습니다. 최종 상태는 22행이 `OCR_REQUIRED`, 2행은
  같은 지표명을 쓰는 다른 프로그램과 겹쳐 `AMBIGUOUS`로 재분류됐고
  (6.5절). `OCR_REQUIRED`·`AMBIGUOUS` 24행 전부 이후 원문 이미지
  육안 확인으로 `review_status=CONFIRMED` 처리됐습니다(9절 3·3-1번).
- 2022~2024년 계획-보고 목표치 불일치 20건 중 다수는 추출 오류가
  아니라 **계획서 목표치와 보고서(성과보고서 별첨3) 목표치가 실제로
  다른 사례**입니다. 보고서의 실적÷목표 계산이 보고서 자체의 공식
  달성률과 자기부합해 추출값이 옳다는 것을 확인했고, 별첨6 변경표
  숫자와도 정확히 일치해 `MATCH_AFTER_CHANGE`/`MANUAL_MISSING_
  PDF_PRESENT`로 재분류했습니다(보완9).
- 이번 결과는 지표 단위 정의·산식 검증용입니다. 어떤 사업이 우수하거나
  부실한지 판정하지 않았고, 프로그램 성과지표를 세부사업 성과로
  귀속하지 않았습니다.

## 1. 대상과 목적

- 대조 기준: `data/processed/performance/program_kpi_year.parquet` 63행
  (2022년 24행, 2023년 26행, 2024년 13행). 한 행은
  `부처 × 프로그램 × 성과지표 × 회계연도`입니다.
- 수기 원본: `data/manual/LLM_문서구조화_중기부_최종.xlsx`,
  `data/processed/performance/manual_performance_rows.parquet`
  (예시행 1개는 대조 모집단에서 제외, 삭제하지 않음).
- 원문: `data/raw/performance_docs/appendix/year={2022,2023,2024}/
  ministry_code=102/` 아래 계획서·보고서 6개 PDF(총 304페이지 중
  2022~2024 6개 파일 사용, 2025년 성과계획서는 페이지 인벤토리에만
  포함하고 63행 대조에는 사용하지 않음).
- 목적: 63행이 원문과 일치하는지 확인해 (1) 자동 확인 가능,
  (2) 계획서-보고서 변경, (3) OCR/사람 검토 필요로 분리하는 것입니다.
  사업 우수·부실 판정, 삭감·폐지 판단은 하지 않습니다.

  추출, 행별 대조(`reconcile_row`), 63행 오케스트레이션

- `tests/performance_pipeline/test_pdf_reconciliation.py`: 순수 함수

  4개 필수 시나리오(완전일치, 지표명 변경, 수기 결측·PDF 존재,

- CLI: `fiscal-performance reconcile-mss-performance-pdfs
  [--overwrite] [--manual-review-confirmations-path PATH]`

- `data/manual/performance/pdf_reconciliation_manual_confirmations.csv`:
  사람이 원문을 직접 확인한 뒤에만 채우는 검수 확정 파일(파이프라인이
  자동 생성하지 않음). `reviewer`/`review_status`/`review_note`/
  `review_confirmed_at` 4개 컬럼을 결과에 병합하며, 수치·판정 컬럼은
  절대 덮어쓰지 않습니다(9절).

## 3. 매칭 규칙

### 3.1 지표명

1. 공백·줄바꿈·괄호·원문자 숫자(①②…)·일반 문장부호를 제거한
   정규화명으로 정확 일치를 먼저 시도합니다(`normalize_indicator_name`).
2. 계획서-보고서 명칭이 다르면 성과보고서 별첨6 변경사항 구간에서
   해당 이름을 검색해 근거 텍스트가 있으면 `MATCH_AFTER_CHANGE`로
   두고, 근거가 없으면 자동으로 동일 지표로 확정하지 않습니다.
3. 문자열 유사도만으로 동일 지표를 확정하지 않았습니다(유사도
   자체를 사용하지 않고 정규화 정확 일치 또는 변경사항표 근거만
   사용).
4. 이번 63행에서는 하나의 PDF 지표가 여러 수기 행에 매칭되는
   `AMBIGUOUS` 사례가 발생하지 않았습니다(0건).

### 3.2 원문 구간

- 계획서: 분리 PDF 1페이지(별첨1 시작)부터 "별첨2" 텍스트가 나오는
  페이지 전까지. 2023·2024년은 페이지 텍스트 블록을 이어붙여
  지표명이 블록 경계를 넘어도 찾을 수 있게 했습니다. 2022년은 표
  셀이 이미지라 페이지를 렌더링해 로컬 Tesseract OCR(한글+영문)로
  재추출합니다.
- 보고서: 별첨3 "3. 세부현황" 표에서 지표명 뒤 "목표/실적/달성률"
  라벨을 앵커로 최근 3개 연도 값을 수집하고 마지막 값(현재 회계연도)
  을 사용합니다. 라벨 뒤 숫자가 한 줄에 여러 개 붙어 있으면
  (예: "100.0% 137.3%") 토큰 단위로 분리해 다음 지표명을 흡수하지
  않게 했습니다.
- 보고서 별첨3 구간에 폰트 매핑이 불완전한 개인용 영역(PUA) 글자가
  있으면(2022년 다수, 2023·2024년 일부) 텍스트로 못 찾은 지표를
  `PDF_NOT_FOUND`로 단정하지 않고 해당 페이지를 OCR로 재시도한
  뒤에도 `OCR_REQUIRED`로 사람 확인을 요구합니다.
- 페이지는 `split_pdf_page`(분리 PDF 기준), `source_pdf_page`(원본
  PDF 기준, 파일명 시작 페이지로 환산), `printed_page`(화면에 보이는
  인쇄 페이지, 확인 안 되면 null)로 분리해 기록합니다.

## 4. 숫자 비교와 달성률 산식

- 쉼표·`%`·공백은 비교용 정규화에서만 제거하고 원문 문자열
  (`*_raw`)과 숫자 변환값(`*_numeric`)을 모두 보존합니다.
- 성과지표 표의 괄호(예: "(4.11)")는 회계 문서의 음수 표기가 아니라
  강조·잠정치 표시로 실제 사용된 것을 확인했습니다. 따라서
  `parse_numeric`은 괄호를 제거만 하고, `-`/`△`가 있을 때만
  음수로 판단합니다.
- 달성률 계산: 상향지표 = 실적÷목표×100, 하향지표 = 목표÷실적×100.
  방향 불명 또는 분모 0이면 `computed_achievement_rate`는 null이며,
  문서에 적힌 공식 달성률(`official_achievement_rate_*`)을 계산값으로
  덮어쓰지 않습니다. 두 값이 모두 있는 58행 중 56행은 반올림 오차
  0.1%p 이내로 일치했습니다. 2행(중기부-2022-II1-03,
  중기부-2023-II1-03, 둘 다 "보상업체 부도율 감소(%)")은 일반
  상향÷하향 공식으로 재계산한 값과 문서의 공식 달성률이 크게
  달라, 이 지표는 단순 실적÷목표(또는 목표÷실적) 비율이 아닌 별도
  산식(예: 전년 대비 개선율 방식)을 쓰는 것으로 추정됩니다. 산식을
  임의로 확정하지 않고 공식 달성률만 그대로 보존했으며, 9절의
  사람 결정 사항에 포함했습니다.
- `indicator_direction` 원본에 `상향66:57`류 오염이 있으면 원본을
  보존한 채 `DIRECTION_PARSE_REVIEW`로 표시했습니다(1건, 중기부
  -2024-I1-01).

### 4.1 변경폭 정량화(왜 바뀌었는지가 아니라 얼마나 바뀌었는지)

`VALUE_MISMATCH`만 표시하고 크기를 계산하지 않으면 63행을 사람이 다시
손으로 빼야 합니다. 변경 **사유**(정책 조정·오류·산식 차이)는 원문
서술이 없으면 판단할 수 없지만, 변경 **크기**는 이미 추출된 두 숫자의
단순 산술이므로 다음 컬럼을 추가해 계산했습니다(`numeric_change`).

- `plan_target_change_abs`/`_pct`: 수기 목표 대비 계획서(PDF) 목표 차이.
- `report_target_change_abs`/`_pct`: 수기 목표 대비 보고서(PDF) 목표 차이.
- `report_actual_change_abs`/`_pct`: 수기 실적 대비 보고서(PDF) 실적 차이.
- `report_achievement_rate_change_abs_pp`: 수기 달성률 대비 보고서(PDF)
  달성률 차이(%p, 비율 재계산 아님).
- **`plan_vs_report_target_change_abs`/`_pct`**: 계획서(PDF) 목표와
  보고서(PDF) 목표 자체의 차이. "계획-보고 목표가 얼마나 바뀌었는지"에
  대한 직접적인 답입니다.
- **`documented_change_target_before_raw`/`_after_raw`/`_reason_raw`**:
  보고서 별첨6 "OO년도 성과계획서 변경 사항" 표에서 같은 지표를 찾아
  옮긴 목표(전/후)와 정부가 적어놓은 수정사유 원문. "**왜**
  바뀌었는지"에 대한 정성적 답입니다(6.2.1절).
- **`documented_change_ocr_conflict`**: 계획서 목표를 OCR로 추출했는데
  별첨6의 "변경 전" 값과 다르면 `True`. 이 경우 OCR값이 틀렸을 가능성이
  더 큽니다(값을 자동으로 바꾸지는 않고 플래그만 남김).
- **`documented_change_report_conflict`**: 별첨6의 "변경 후" 값과
  보고서 별첨3에서 직접 추출한 목표가 다르면 `True`(두 원문이 서로
  어긋난다는 뜻이라 사람이 봐야 함). 실제 데이터에서는 0건입니다.

계획서·보고서 목표가 둘 다 있는 59행 중 36행은 변경이 없고(동일),
23행은 변경됐습니다. 변경된 행 중 13행은 변경률 10%p 이상, 5행은
50%p 이상이며 변경된 행의 변경률 중앙값은 약 12.5%입니다. 10%p·50%p
구간은 정책 기준이 아니라 스캔을 돕는 서술적 구간입니다.

`review_reason`은 문제 유형을 코드값으로만 담고 있어, 어느 파일·몇
쪽을 열어봐야 하는지는 검토자가 여러 페이지 컬럼을 직접 조합해야
했습니다. **`review_instruction`**은 이미 계산된
`plan_split_pdf_page`/`report_split_pdf_page`/
`documented_change_split_pdf_page` 등을 새로 추정하지 않고 그대로
조합해 `[계획서] 파일명 N쪽(원본 M쪽) / [보고서] ... / [별첨6 변경표]
...` 형태의 한 줄 안내문을 만듭니다(`EXACT_MATCH`/`NOT_APPLICABLE`인
행은 볼 필요가 없어 비워둠). 지표명 충돌로 `AMBIGUOUS`인 행에는
"동일 연도 내 지표명 중복 - 프로그램별 위치를 직접 대조하세요" 문구를
앞에 붙입니다.

## 6. 불일치 유형과 대표 사례

### 6.1 2022년 전체가 OCR 필요한 이유

2022년 성과계획서 별첨1의 목표치 표는 41페이지 중 프로그램 성과지표
현황이 있는 1~3페이지를 포함한 12페이지가 텍스트 레이어 없는 이미지
표입니다(화면 렌더링으로 표 존재를 직접 확인). 로컬 Tesseract OCR로
재추출한 결과 목표치 다수가 수기값과 일치했지만
(`plan_target_match_status=EXACT_MATCH` 19/24행), OCR은 표 구조를
깨뜨릴 위험이 있어 "OCR로 값을 찾음"과 "원문을 자동 확정함"을
구분했습니다. 즉 2022년 24행은 **개별 값은 대부분 그럴듯하게
일치하지만, 이미지 표 자체를 사람이 화면으로 한 번 더 확인하기
전까지는 자동 확정하지 않는다**는 보수적 원칙을 적용한 결과입니다.
- 2022년 보고서 별첨3 구간(30/43페이지가 270도 회전 표, 다수 PUA
  글자 포함)에서 지표명 자체를 못 찾은 2행은 OCR 재시도 후에도
  `report_name_match_status=OCR_REQUIRED`로 남았습니다
  (중기부-2022-III1-02, IIII1-02). 2023년에도 동일 사유 2행
  (중기부-2023-III1-02, IIII1-02)이 있어 전체 4행입니다.

`documented_change_target_after_raw`, `documented_change_reason_raw`,

실제 조정 사유가 있습니다(실적 기반 상향/현실화 6건, 사업비 증액에
따른 재산정 1건, 합계 오기 정정 1건). **어느 것도 "정책 실패"나
"목표 임의 조작"이 아닙니다.**

  2023년 목표는 27.7%, 실적 44.3%, 공식 달성률 159.9%
  (44.3÷27.7×100=159.9%로 자기부합, 추출 오류가 아님을 확인).
  왜 13배 이상 다른지는 별첨6에 사유가 명시돼 있습니다: `'22년 실적치
  고려하여 최근 5년간 평균증가율 반영하여 '23년 목표 상향조정`
  (6.2.1절 참고).
- 예: 중기부-2024-I2-02 "혁신바우처..." 유형처럼 실적·공식 달성률은
  보고서와 완전히 일치하지만(EXACT_MATCH) 목표치만 계획서(50.4)와
  보고서(51.5)가 달라 별첨6 변경표로 확인해
  `report_target_match_status=MATCH_AFTER_CHANGE`(보완9 재분류
  이전에는 `VALUE_MISMATCH`)인 행이 4건 있습니다(2024년
  `I2-02`·`II1-02`·`II2-01`·`III1-01`). 보고서의 달성률 계산은
  보고서 자체 목표(51.5)를 분모로 쓴 것으로 확인됩니다.
- 2023년 12행은 수기 실적치·공식 달성률이 전부 결측(`None`)이면서
  동시에 보고서 목표치가 계획서와 다른 행입니다. 즉 수기 구조화
  단계에서 실적·달성률이 아예 입력되지 않은 상태이며, 계획-보고 목표
  변경 여부와는 별개 이슈로 분리해서 봐야 합니다.

  PDF_MISSING_MANUAL_PRESENT`로 남았습니다. 수기값은 실적 4.1,
  달성률 100%로 이미 채워져 있어 원문 재확인(해당 페이지:
  성과보고서 분리 PDF 4페이지, 원본 162페이지)이 필요합니다.

### 6.5 데이터 분석가 관점 재검증 — 교차검증 결과와 지표명 충돌 버그 발견

수집이 끝난 뒤 "수집한 값 자체가 맞는지, 설득력이 있는지"를 데이터
분석가 관점에서 다시 검증했습니다(수집가 관점 = "추출됐는가",
분석가 관점 = "그 값이 정말 맞는가"). 63행 전체를 대상으로 **서로
독립적인 두 원문 소스**를 교차검증했습니다.

**검증 1 — 별첨6(변경 후) vs 별첨3(직접추출), 독립 소스 비교**
: 둘 다 있는 59행에서 차이는 **0/59건**(모두 정확히 일치). 별첨6
파싱과 별첨3 파싱이 서로 다른 코드 경로인데도 완전히 일치해,
두 파싱 로직 모두 신뢰할 수 있다는 강한 근거입니다.

**검증 2 — 별첨6(변경 전) vs 별첨1(텍스트 추출), 독립 소스 비교**
: 별첨1이 "별첨6 값을 그대로 가져온 것"이 아니라 실제 텍스트에서
독자적으로 뽑힌 39행만 비교했더니, 불일치가 **정확히 2건**이었고
그 2건은 6.2.1절에서 이미 `documented_change_ocr_conflict=True`로
확정한 **바로 그 2022년 OCR 오류 행**이었습니다. 즉 이 교차검증이
새로운 문제를 더 찾아내지는 않았지만, 기존에 "OCR이라 의심된다"고
판단한 것이 실제로 원문 기준으로도 유일한 불일치였다는 것을
독립적으로 재확인했습니다.

**검증 3 — 같은 연도 내 지표명 중복 확인, 새로 발견한 버그**
: 수기 63행의 지표명을 연도별로 그룹화했더니, 2022년에 **서로 다른
두 프로그램(Ⅱ-1, Ⅲ-1)이 완전히 동일한 지표명("자금공급 수혜
중소기업 매출액 증가율")을 쓰는 사례**가 있었습니다. 이 저장소의
모든 PDF 매칭 함수(`extract_plan_evidence`,
`extract_report_achievement_evidence`, `find_change_evidence`)는
"그 연도 PDF 안에서 지표명과 일치하는 첫 번째 위치"만 찾기 때문에,
두 프로그램이 이름을 공유하면 **두 수기 행이 같은 PDF 근거 하나를
그대로 나눠 갖게 됩니다**. 실제로 확인한 결과 `중기부-2022-III1-03`
(창업환경조성, Ⅲ-1)행이 `중기부-2022-II1-01`(중소기업성장안정지원,
Ⅱ-1)의 목표값(8.13)을 잘못 가져오고 있었습니다(Ⅲ-1의 실제 원문
목표는 16.6이며, 수기 목표치 16.6·`report_target_match_status=
VALUE_MISMATCH`로 이미 신호는 있었지만 원인이 "충돌"이라는 것은
표시되지 않았습니다).

**조치**: 63행을 만드는 시점에 연도별 지표명 중복을 자동 탐지해
해당 행들을 `AMBIGUOUS`로 재분류하는 `_flag_indicator_name_collisions`
검증 단계를 추가했습니다. 값을 추정해서 고치지는 않았고(원본 보존
원칙), `review_reason`에
`INDICATOR_NAME_AMBIGUOUS_MULTIPLE_PROGRAMS_SAME_YEAR`를 남겨 "이
행의 PDF 근거는 다른 프로그램 것과 뒤섞였을 수 있다"는 것을
명시했습니다. 실제 데이터에서는 이 2행(둘 다 2022년, 5절 표에 반영)
뿐이었고, 다른 61행에는 이 위험이 없었습니다.

**분석가로서의 결론**: 검증 1·2는 "이미 확정한 것이 맞다"는
확인이라 새 발견은 아니지만, 검증 3은 **63행 중 2행이 실제로 잘못된
PDF 값을 갖고 있었다는 새로운 발견**입니다. 다만 두 행 모두 원래도
2022년이라 `OCR_REQUIRED`(자동 확정 금지)였고 하나는 이미
`VALUE_MISMATCH`였기 때문에, "사람이 검토해야 한다"는 결론 자체는
바뀌지 않았습니다. 바뀐 것은 **"왜" 검토해야 하는지가 명확해졌다는
점**입니다(OCR 품질 문제가 아니라 지표명 충돌 문제). 표본이 63행뿐이라
이런 충돌이 다른 부처·연도에서 얼마나 자주 나타나는지는 이 결과만으로
일반화할 수 없습니다.

  - 2022년 보고서(별첨3 세부현황, 270도 회전·PUA 글자 구간):
    분리 PDF 5~9페이지.
  - 2023년 보고서(지표명 자체가 PUA 글자로 깨져 OCR 재시도 후에도

  않았고, PyMuPDF 렌더링 + 로컬 Tesseract(kor+eng)만 사용).

## 8. 수기자료를 그대로 쓸 수 있는 행과 쓸 수 없는 행

(2026-07-28 갱신: 63행 중 검수가 필요했던 49행 전부
`review_status=CONFIRMED`로 확정됐습니다 — 보완7·8·9, 아래 9절.
"확정 여부"와 "라벨"은 서로 다른 축입니다. 확정됐어도 라벨이
`MANUAL_MISSING_PDF_PRESENT`·`OCR_REQUIRED`·`AMBIGUOUS`이면 "원문
근거는 확인됐지만 수기 엑셀 자체에는 아직 채워지지 않은 값이 있다"는
뜻으로, 수기 엑셀을 그대로 프로그램 재정 분석에 쓰기 전에 PDF값
반영이 필요하다는 사실은 남아 있습니다.)

- **그대로 사용 가능(14행, `EXACT_MATCH`)**: 계획서·보고서 지표명,
  목표치, 실적치, 공식 달성률이 모두 원문과 일치. 프로그램 재정 분석
  등에 참고 지표로 사용 가능.
- **목표치 변경만이었고 완전 해소(7행, `MATCH_AFTER_CHANGE`)**:
  지표명 변경 또는 목표치 사후 개정이 별첨6 공식 근거로 확인됐고,
  실적·달성률까지 수기값=PDF값이 일치합니다. 그대로 사용 가능합니다.
- **원문 근거는 확인됐으나 수기 엑셀에 실적·달성률 보완이 필요
  (15행, `MANUAL_MISSING_PDF_PRESENT`)**: 목표치 개정은 별첨6로
  확인됐지만, 수기 엑셀의 실적·공식 달성률 칸이 비어 있고 PDF에는
  값이 있습니다(2022년 2건 + 2023년 12건 + 2024년 3건). 전부
  `review_status=CONFIRMED`로 원문 값을 확인했으므로(9절), 수기
  엑셀에 그 값을 채워 넣는 별도 작업(이번 파이프라인 범위 밖, 원본
  수기 엑셀 읽기 전용 원칙) 전까지는 수기 엑셀만으로 프로그램 재정
  분석을 하면 실적·달성률이 결측으로 보입니다.
- **원문 이미지·회전·PUA 글자 구간 확인 필요(24행, `OCR_REQUIRED`)**:
  전부 `review_status=CONFIRMED`로 사람이 페이지 이미지를 직접
  대조했습니다(9절 3번). 확정된 값은 수기값과 대부분 일치했지만,
  원본 PDF 표 구조상 자동 확정 라벨(`EXACT_MATCH`)로는 바꾸지
  않았습니다(자동 OCR 매칭만으로 최종 확정하지 않는다는 원칙).
- **동일 지표명 충돌(2행, `AMBIGUOUS`)**: `review_status=CONFIRMED`
  로 확인됐지만(9절 3-1번), 어느 프로그램의 PDF 근거인지 텍스트
  검색만으로는 구조적으로 구분할 수 없다는 한계가 라벨에 남아
  있습니다.
- **PDF 미기재(1행, `PDF_MISSING_MANUAL_PRESENT`)**: 원문 재확인이
  필요합니다(6.4절).
