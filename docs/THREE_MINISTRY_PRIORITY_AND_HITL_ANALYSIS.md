# 3개 부처 성과·재정 결합, 순위 안정성, 원문 검수 설계

> 기준일: 2026-07-29  
> 대상: 고용노동부 `019`, 보건복지부 `075`, 과학기술정보통신부 `162`  
> 상태: 탐색 파일럿, 최종 정책 우선순위 아님

## 1. 결론

중기부 파일럿의 성과·재정 결합과 복수 시나리오 분석을 3개 부처에
재사용할 수 있었습니다. 다만 전체 3개 부처를 한 번에 줄 세운 결과는 가중치에
충분히 안정적이지 않습니다.

- 분석행 340개 중 공동분석 306개, 점검 후보 209개, 시나리오 순위 적격
  164개입니다.
- 전체 순위의 시나리오 간 Spearman 상관은 `0.681~0.935`이지만, 네 시나리오
  공통 Top 5는 `0행`입니다. 공통 Top 10도 `2행`뿐입니다.
- 따라서 하나의 전체 최종 순위를 발표하면 안 됩니다. 전체 결과는 부처를
  가로지르는 후보 탐색에만 쓰고, 실제 검토 순서는 부처별 순위와 원문 검수를
  함께 사용해야 합니다.
- 3개 부처 PDF 대조 361행 중 332행은 출처·페이지·원문 근거로 승인했고,
  출처나 지표 대응을 사람이 판단해야 하는 29행만 검수 대상으로 남겼습니다.
  자동 근거 승인은 사람 검수로 기록하지 않습니다.

|---|---:|---:|---:|---:|---:|

부처별 원본 해시와 재정 집계 전후 본예산·예산현액·결산액 차이는 0원입니다.
과기정통부의 프로그램명 미매칭 27개는 임의로 연결하지 않았습니다.

각 부처의 보고서 대표 페이지를 다시 렌더링해 표·글자·쪽 번호가 검수 화면에서
읽을 수 있는지 확인했습니다. 이 렌더링 확인은 개별 361행의 값 확정을 뜻하지

### 2.3 성과·재정 결합과 후보 생성

| 부처 | 결합 분석행 | 공동분석 | 데이터 검증 | 점검 후보 | 순위 적격 |
|---|---:|---:|---:|---:|---:|

| `075` | 116 | 113 | 24 | 86 | 63 |

한 행의 기준은 `부처 × 프로그램 × 회계연도 × 회계유형`입니다. 프로그램
성과를 세부사업 성과로 배분하지 않았고, 세부사업은 재정 원인 확인에만
사용합니다.

## 3. 우선순위 기준과 결합 방식

현재 순위는 정답 라벨이 없는 상태의 설명 가능한 탐색 순위입니다.

| 구성요소 | 산식 | 역할 | 주의 |
|---|---|---|---|
| 성과 격차 | 목표 미달 지표 수 / 비교 가능한 지표 수 | 성과 설명 필요 정도 | 지표별 달성률을 평균하지 않음 |
| 집행관리 | 현재 저집행 강도, 반복 저집행 예산비중, 반복 연말집중 예산비중의 최댓값 | 집행 설명 필요 정도 | 낮은 집행률을 낭비로 판정하지 않음 |
| 성과·예산 괴리 | 성과 격차×예산 급증 비중과 성과 양호×예산 급감 비중의 최댓값 | 흐름의 불일치 탐색 | 감액 원인을 성과로 단정하지 않음 |
| 재정영향도 | 본예산 백분위 | 검토 영향도 보정 | 규모만으로 후보를 만들지 않음 |

결측 구성요소를 0점으로 바꾸지 않았고, 남은 구성요소에 가중치를 재배분하지
않았습니다. 데이터 신뢰도는 점수 가중치로 쓰지 않고 별도 `DATA_REVIEW`
게이트로 사용했습니다. 신뢰도가 낮은 행에 낮은 점수를 주면 데이터 오류가
정책 우선순위 뒤로 숨기 때문입니다.

비교 시나리오는 다음 네 가지입니다.

- 균등가중: 각 25%
- 성과중심: 성과 50%, 집행 20%, 괴리 20%, 재정영향 10%
- 집행중심: 성과 20%, 집행 50%, 괴리 20%, 재정영향 10%
- 재정영향 보정: 성과 20%, 집행 20%, 괴리 20%, 재정영향 40%

## 4. 전체 순위와 부처별 순위를 분리한 이유

전체 순위에서는 같은 연도의 3개 부처 전체에서 본예산 백분위를 계산합니다.
부처별 순위에서는 `부처 × 연도` 안에서 다시 백분위를 계산합니다.

보건복지부처럼 절대 예산규모가 큰 부처가 전체 재정영향도 상단을 차지하는 것은
전체 관점에서는 맞지만, 그 값을 그대로 부처 내부 순위에 쓰면 작은 부처의
중요 사업을 과소평가합니다. 성과·집행·괴리 산식은 동일하게 유지하고
재정영향도 기준집단만 바꾼 이유입니다.

## 5. 순위 안정성 결과

### 5.1 전체 3개 부처

- 시나리오 간 Spearman: `0.681~0.935`
- 순위 범위 중앙값: `31.5위`
- 최대 순위 범위: `105위`
- 네 시나리오 공통 Top 5: `0행`, 합집합 `10행`
- 네 시나리오 공통 Top 10: `2행`, 합집합 `20행`

상관계수는 대체로 양수지만 상위권 구성은 안정적이지 않습니다. 전체 순위는
단일 번호보다 `시나리오별 순위 범위`, `공통 Top K 여부`, `점검 신호 유형`을
보여주는 것이 타당합니다.

### 5.2 부처별

## 7. 휴먼인더루프 화면

`src/fiscal_dashboard/app.py`는 `시작 → 데이터 확인 → 후보 분석 → 기준 비교
→ 원문 검수` 순서로 한 단계씩 표시합니다. 후보 분석에서 고른 프로그램은 원문
검수 단계의 해당 성과지표로 이어집니다. 원문 검수 화면은 다음을 제공합니다.

- 공통 부처·연도 필터와 미검수 필터
- 수기값과 PDF 추출값 비교
- 계획서·보고서·성과계획 변경표 페이지 이미지
- 자동 판정·검수 사유·추출 텍스트
- 검수자, `PENDING/CONFIRMED/CORRECTED/NOT_RESOLVABLE`, 검수 메모를
  저장하고 다음 지표로 이동

검수 결과는 원본이나 자동 추출값을 덮어쓰지 않고
`data/manual/performance/pdf_reconciliation_manual_confirmations.csv`에
별도로 남습니다. 따라서 누가 어떤 근거로 승인·수정했는지 추적할 수 있습니다.

## 8. LLM 적용 결정

현재 29행은 출처나 지표 대응을 사람이 판단해야 하므로 LLM에 보내지 않습니다.
LLM은 향후 새 PDF를 처음 구조화할 때 후보 페이지의 좁은 근거 묶음만 처리하는
비에이전트형 배치로 사용합니다.

```text
후보 페이지 고정
→ 저가 LLM JSON 추출
→ 코드 검증
→ 실패·불일치만 상위 LLM 재검수
→ 사람 승인
```

LLM 결과의 자기신뢰도는 쓰지 않습니다. 스키마, 근거 문장 존재, 페이지 범위,
수기·규칙·두 모델의 일치, 사람 수정 여부를 추적합니다. 구체적인 호출 감사
필드와 평가 설계는 `docs/OCR_LLM_PERFORMANCE_PIPELINE_PLAN_AND_FUNCTIONAL_SPEC.md`
에 기록했습니다.

## 9. 이번 작업에서 자동화한 것과 남긴 것

자동화:

- `fiscal-analytics analyze-three-ministry-priority-scenarios --root . --overwrite`
  한 번으로 3개 부처 동년도 결합, 통합표, 전체·부처내 시나리오 순위, 안정성
  산출물을 다시 만듭니다.
- 프로그램 매칭 실패, M3 신호 미연결, 회계별 금액 불일치를 실패로 숨기지 않고
  데이터 검증 큐로 분리합니다.
- 대시보드에서 PDF 페이지 확인과 사람 검수 기록을 연결합니다.

자동화하지 않은 것:

- 프로그램코드가 없는 수기 행의 임의 연결
- `CORRECTED` 메모의 자동 분석값 승격
- LLM API 호출
- 단일 최종 복합점수와 정책 우선순위

이 항목들은 공식 근거, 필드별 수정 스키마, API 승인, 이해관계자 임계값 합의가
각각 필요하므로 현재 자동화하면 재현성보다 오판 위험이 큽니다.
